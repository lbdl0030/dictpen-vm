# 固件包开发教程

写给要往 dictpen-vm 里**加一台新机器**的人。目标：让新机器的固件在这个框架里跑起来，
而**不用改框架核心**。

> **先读 [`docs/插件模型.md`](插件模型.md)** —— 那份讲"框架里有哪些插件点、各自的接口与契约"，
> 是**唯一**写契约的地方。本篇只讲**怎么动手**：每一步做什么、看什么、怎么验证。
> 卡住了看 [`docs/疑难排查.md`](疑难排查.md)（按现象查）。

## 1. 先搞清自己要做哪一类

| 你的情况 | 动哪个插件点 | 预计工作量 |
|---|---|---|
| 镜像能挂、内核能用，只是参数/补丁不同 | 只写包（①③④） | 小 |
| 同族机器，配置几乎一样 | 复制一个现成包改路径 | 很小 |
| 镜像格式/内核/显示设备与现役 runtime 都不同 | 加一个 runtime（②）+ 写包 | 大（大头是平台差异研究） |
| 厂商合成器依赖专有硬件 | 写包（③，包内整包换合成器） | 中~大 |

一个可用的判据：**如果"引导方式"和现役四个 runtime 里某个一样，就不要写 runtime。**
现役四个：`rv1106-linux-erofs`、`cv18xx-linux-ext4`、`cv18xx-linux-erofs`、`rockchip-linux-ext4`
（差异表见 `docs/插件模型.md` §4.4）。

## 2. 最快的上手方式（同族机器）

```bat
:: 1. 复制一个最像的包（资源管理器里复制也行）
xcopy /E /I packs\a6pro packs\mydev

:: 2. 改 packs\mydev\pack.toml：name 改成 mydev，镜像路径改成你的
::    把新镜像放进 packs\mydev\images\

:: 3. 校验 + 启动
python scripts\dpctl.py packs mydev
python scripts\dpctl.py up --pack mydev --display none
python scripts\dpctl.py screenshot --out vm\shots\mydev.png
```

`packs mydev` 会列出缺文件与 MD5 不符，照着提示补即可。
**先别急着删 a6pro 的补丁，也别急着抄** —— 尤其 HAL 那类替换，见 §5.2 的警告。

## 3. pack.toml 实操

字段的**全量契约表**在 `docs/插件模型.md` §3.2（字段/类型/缺省/校验时机/失败表现都在那）。
这里只讲动手时最容易踩的几条：

- 所有路径**相对包目录**（也可写绝对路径）。
- `[platform].kernel` / `initrd` **留空就用框架的**通用内核与通用 initramfs。只有当这个平台
  必须自带内核时才填。
- `[display]` 的 `xres/yres` **必填**：它既给虚拟显示设备，又用来现算 EDID
  （框架不知道任何分辨率）。填错的表现：UI 缩在角落 / 被裁 / 斜切。见 §6.1。
- `[checks]` 是**硬校验**：对不上 `up` 直接拒绝启动（`packs <名>` 只提示）。两种写法都行：
  ```toml
  [checks]
  "images/x.img" = { md5 = "…" }      # 表形式
  "images/x.img" = "…"                # 直接给字符串（x6pro 用这种）
  ```
- `[state].size_mb`：**只有创建状态盘时生效**（`up --fresh`，或删掉 `vm/state-<包>.img` 再 `up`）。
  为什么值得由包声明：overlay 的 upper 层就住这块盘上，盘一满 overlay 退化成只读，
  所有 guest 适配全部失败（表现为黑屏 + 服务反复重启）。各机型 `/userdata` 占用差别很大。
- `[client].profile` 找不到**只告警**，不影响开机。

## 4. 声明式适配：能声明就别写脚本

`[adapt]` 里的键（`logo` / `touchbridge` / `cfg_overlay` / `battery` / `license` / `ap`）
都是"你声明、框架按语义执行"，语义详见 `docs/插件模型.md` §5.1。它们的好处是
**时机与"只改列出的键"这些纪律由框架兜住**，不必自己写脚本。

### `cfg.json.overrides` 的格式

```ini
# 每行一个 key=value；空行与 # 开头忽略
width=800              # 值以数字开头 -> 按 JSON 数字替换 "width": <n>
height=254
direction=0
dbuffer=false          # true|false -> 按 JSON 布尔替换
tp=/dev/input/by-path/axs_ts   # 值以 / 开头 -> 按 JSON 字符串替换 "tp": "<s>"
```

框架只改你列出的键，**其余一个字节都不动** —— 这正是"框架不污染别的机器"的落点。
**注意：覆盖不了空字符串**（值只有"数字 / 以 `/` 开头 / `true|false`"三类），
需要清空某个键（例如把 `device.mouse` 置空）时，要在包内钩子里用 `sed` 补一次（§5）。

### 常见现象的对照表（先查这个，再上脚本）

| 现象 | 大概率是 |
|---|---|
| UI 缩在角落 / 窗口比例不对 | `[display]` 的 `xres/yres` 填错了（EDID 由它生成） |
| 画面斜切 / 斜条 | `cfg_overlay`：`direction=0`（通常还要一起改 `width/height`） |
| 颜色不对 / 画面花 | `cfg_overlay`：`bpp=32` |
| 完全没有画面（停在启动图或黑屏） | 先看 `docs/疑难排查.md` §1：多半是加载链断了或 HAL 要换 |
| 进桌面约 1 分钟后自己关机 | `battery = true` |
| 点击没反应 / 只能点一下 | `touchbridge` + `cfg_overlay` 的 `tp=` 指向桥创建的设备（§6.2） |
| 停在激活页 | `license = true` |
| 网络页里没有可连的热点 | `ap = true` |
| 应用说"需要联网"其实网通 | 包内钩子模拟厂商芯片节点（`docs/疑难排查.md` §3） |

## 5. 命令式适配：hooks / replace / extra

三个手段的语义在 `docs/插件模型.md` §5.2。这里讲**怎么写**。

### 5.1 `hooks` 的执行环境

- 跑在 initramfs 的 busybox sh 里、**switch_root 之前**（是框架适配的**最后一步**，
  见 `docs/插件模型.md` §5.3 的顺序表）。
- 因此：**用 POSIX sh**；只能用 initramfs 里的命令，要跑 guest 的命令得 `chroot "$TARGET" …`。
- 可用变量：`$TARGET`（guest 根，可写）、`$OVERLAY`、`$STATE_OK`、`$INIT`，
  以及 `pack.env` 的 `PACK` / `RUNTIME` / `PANEL` / `ADAPT_*`。
- 钩子必须**幂等**（每次开机都会跑），并且不依赖别的包存在。
- 每个钩子往内核日志里打自己的结果（`echo "pack hook: …" >/dev/kmsg` 或普通 stdout），
  便于在串口里核对。

### 5.2 `replace`：覆盖 guest 文件

```toml
[adapt.replace]                       # 键 = 包内路径，值 = guest 绝对路径
"patches/libfalcon.so" = "/usr/lib/libfalcon.so"
"patches/runDictPen.sh" = "/usr/bin/runDictPen"
```

- 框架**只按表搬运**，不解释文件是什么（所以框架里连 HAL 的名字都不出现）。
- 文件在 initrd 里按 **basename** 平铺到 `/patches/`，`replace.list` 也用 basename 指它
  —— 因此**同包内不要有两个同名文件**要覆盖到不同位置。
- 也常用来**投送压缩包**（x6pro 就投了两个）：
  ```toml
  "weston.tar"  = "/userdata/weston.tar"     # 25 MB 的合成器载荷
  "desktop.tar" = "/userdata/desktop.tar"
  ```
  然后在包内钩子或自装的 rcS 脚本里解包。

> ⚠ **换 HAL/启动脚本这类替换必须逐机型验证。** 同类库的不同**版本**行为不同：
> 照抄别的机型打过补丁的 HAL 会崩（`docs/疑难排查.md` §1 有实例）。
> 换厂商启动脚本时，"与厂商原版一致"的部分（尤其环境变量）要**逐字**核对 ——
> 一个真实事故是替代 `runDictPen` 时漏了 `LD_LIBRARY_PATH` 的两段路径，
> 结果 jsapi 加载链断掉、退回"验证引导"、全黑。

### 5.3 `extra`：给钩子备素材

```toml
[adapt].extra = ["patches/perl-tree",     # 目录：整棵树原样进 /patches/perl-tree/…
                 "patches/arm64-tree"]     # 目录递归展开，树内保持相对结构
```

单文件会**按包内文件名平铺**进 `/patches/`（与 `replace` 的键一致）。
用途：备用的 Debian 二进制（`strace`/`dropbear`/perl）、初始化用的 tar、字体等。
钩子里再 `cp -rf` 到 `$TARGET` 的对应位置。

### 5.4 `hooks` 能干的三类活（x6pro 是完整范例）

`packs/x6pro/patches/prepare.sh` 是一个把三类动作都做全的例子（可当模板抄）：

1. **停用厂商的实机专用 init**：把不需要的 rcS 脚本 `mv` 到 `$TARGET/etc/vm-disabled/`
   （不要在源镜像上改；overlay 上的改动是持久的，不用每次重来）。
2. **装自己的 rcS 脚本**：写 `$TARGET/etc/init.d/S9x…` 并 `chmod 755`，
   接管厂商脚本没做好的事（起合成器、配网络、挂 udev 规则）。
3. **投送与播种**：把 `replace` 送来的 `*.tar` 解到 `/userdata`，
   或在首次开机时 seed 一份 `/userdata`（幂等：用 `.vm-seeded` 之类的标记文件）。

框内约定：**框架的 initramfs 永远不含机型内容**；你要加的任何东西都放在包里，
由包内钩子在 `$TARGET` 上落位。改框架的 `initramfs-init.sh` 是下策（影响所有包）。

## 6. 显示与触摸（最容易返工的两块）

### 6.1 面板尺寸 ≠ UI 版式

不少机型的 `cfg.json` 是"竖扫方向 + 显示引擎旋转"（例如 `width=254 height=800 direction=270`），
而应用的 UI 版式是横的。**包要做的是让三者一致**：

- `[display]` 用 **UI 版式**的尺寸（横屏），并据此生成 EDID；
- `cfg_overlay` 把 `width/height/direction` 归一化到同一个坐标系（常见是 `direction=0`）。

实测过的两种正解：
- 同族横屏（s6pro 640×260、x5pro 800×254）：`[display]` 与 cfg 都写横屏 + `direction=0`。
- 某些机型反过来（a7pro）：UI 版式跟着 **主题**走，主题查表失败会回退到固件里的
  `MOCK_THEME`（默认 `theme-melon` 按 960×266 排版），于是 1:1 画进小屏就被裁 ——
  这时在包内 `runDictPen.sh` 里钉一行 `export MOCK_THEME=theme-y09` 即可。

判断"是没画还是画错"的快速方法：看 `dpctl screenshot` 出来的 PNG **字节数**
（≈400 B = 一个字都没画；几十~一百多 KB = 画了但版式不对）。详见 `docs/疑难排查.md` §0。

### 6.2 触摸桥

宿主窗口的点击到 guest 是**鼠标事件**，笔的 UI 要**触摸事件**。中间靠包声明的
`touchbridge` 脚本翻译（原理见 `docs/插件模型.md` §6.4）。写/改桥时记住三条：

1. **`UI_SET_*BIT` 系列 ioctl 的参数是"位号本身"**（按值传）。写成 `pack('i',$x)` 会把
   缓冲区地址当位号传进去，内核一律 `EINVAL`，设备能力位全空（`B: EV=1`），
   应用直接忽略这个设备 —— 表现为"点了没反应"，而桥自己的日志看起来一切正常。
2. **坐标是状态，不是边沿。** QEMU 对未变化的绝对轴会去重，所以"按下"那一帧里可能
   **没有** ABS；任何"本帧收到坐标才处理"的写法都会把按下吞掉（点不通、滑不动同一个根因）。
3. **上报的坐标系要与 `cfg.json` 配套**：`tp_direction`/`tp_xoffset`/`tp_yoffset` 决定应用
   怎么变换你上报的坐标，桥不要自己去猜应用的变换。
4. 上报量程（uinput 的 absmin/absmax）要与受端预期一致，否则坐标整体偏移。

## 7. 引导 runtime：换引导方式时才写

**什么时候需要**：镜像格式与现役四个 runtime 都不同；内核必须是厂商的；显示设备不能通用；
厂商模块 `insmod` 报 `invalid format`（与通用内核不兼容）。

**怎么写**：往 `scripts/runtimes/` 丢一个 `.py`（骨架与接口见 `docs/插件模型.md` §4.1），
**不用改 `runtimes/__init__.py`** —— 宿主会扫这个目录自动注册（§4.2）。
拿 `scripts/runtimes/rv1106_linux.py`（60 行左右）当最简参考；
`rockchip_ext4.py` 是"要自己校验镜像格式"的例子。

三条契约别违反（否则会拖垮宿主）：
顶层不做副作用；试验文件用 `_` 开头命名；单个文件坏了不要影响别人（宿主已兜住，但别故意）。

```bat
:: 写完这样验：新增的 name 应该出现在列表里，而 __init__.py 原文 grep 不到它
python scripts\dpctl.py packs
python scripts\dpctl.py packs mydev      :: 应该看到 runtime 而不是"未实现"
python scripts\dpctl.py up --pack mydev --display none
```

> `packs/s7pro/` 是一个**故意不提供 runtime** 的历史例子：它在框架里跑不起来，
> 但框架会明确说"该平台 runtime 未实现"，而**不会**拿别的机型的补丁去覆盖它。
> 平台差异研究（厂商内核、模块、面板时序）是这件事的大头；框架侧只需要那一个文件。

## 8. 调试与自检

### 8.1 看 guest 到底套用了什么

```bat
python scripts\dpctl.py sh -c "cat /proc/cmdline"
python scripts\dpctl.py sh -c "dmesg | head -120"
python scripts\dpctl.py screenshot --out vm\shots\s.png --zoom 2
```

串口日志（每次开机重写）在 `vm/serial.log`；QEMU 自身输出在 `vm/qemu.log`。
适配步骤都会往内核日志打自己的结果，常用关键字：

```
### pack: <包名> runtime=<runtime> panel=<WxH> ###      <- 包已生效
### <ext4|erofs> root mounted ###                        <- 镜像格式对
### state: ext4 created and mounted ###                  <- 状态盘就绪
### overlay: persistent upper ###                        <- 可写根就绪
cfg.json: applied N override(s) from the pack           <- cfg 覆盖生效
pack hook: <钩子名>                                     <- 你包的钩子跑了
### switch_root -> /mnt, init /sbin/init ###             <- 交棒给固件
```

### 8.2 改坏了 `/userdata` 怎么办

```bat
python scripts\dpctl.py down
python scripts\dpctl.py up --pack mydev --rescue     :: 不进笔的 UI，串口给 root shell
:: 串口里干活（console.cmd 或 dpctl sh --serial），或干脆 --fresh 重来
```

`--rescue` 下没有 SSH/adb，只能用串口。

### 8.3 改了框架的 initramfs 之后

```bat
python scripts\build-initramfs.py            :: 重打通用 initramfs
bash -n scripts\initramfs-init.sh            :: 顺手语法检查（busybox sh 容忍度低）
```

**必须重打**：每包 initrd 的缓存指纹里记着 base initramfs 的 md5，不重打就永远复用旧的那份
（改动看起来"没生效"）。

### 8.4 包内容的自检

```bat
python scripts\dpctl.py packs mydev                  :: 文件就位 + MD5
python scripts\dpctl.py pack export mydev -o dist\mydev.dpm
python scripts\dpctl.py pack import dist\mydev.dpm --force
python scripts\package.py --check                    :: "可传播代码包"自检（见 §9）
```

## 9. 分发

| 用途 | 手段 | 带什么 |
|---|---|---|
| 整包搬运（含镜像） | `dpctl pack export/import`（单个 `.dpm`） | 整个包目录 |
| 对外发"可传播代码包" | `python scripts\package.py` | 框架代码/文档 + 各包**描述性文件** |

固件包在"可传播代码包"里默认只带 `pack.toml` / `README.md` / `cfg.json.overrides` /
`touchbridge.pl` 四项。想额外带上自己的说明文件（例如 `DEVLOG.md`），**在包里声明**，
不用去改框架的 `scripts/package.py`：

```toml
[dist]
include = ["DEVLOG.md"]         # 包内相对路径
```

纪律：`*.img` / `*.so` / `*.pem` / `id_*` 会被**硬拦截**（声明了也不放行，且自检直接报错）。

镜像版权归网易有道：只在自己机器之间搬，是否外传由你决定。

## 10. 包内文档模板

一个包建议放两份文档，分工固定：

### `README.md`（开箱信息，必写）

```markdown
# <机型名>

一句话：平台 / SoC / 固件版本 / 这块做到哪一步了。

## 1. 文件来源           镜像从哪来、MD5 是多少、版权声明
## 2. 能力现状           用表格逐项列：引导/UI/触摸/网络/激活/…，✅ 还是 ⛔ 以及原因
## 3. 与同族包的差异      这台为什么和别人不一样（平台/镜像格式/合成器/…）
## 4. 关键适配            包内每个 patches/ 文件是干什么的、为什么需要
## 5. 复现与验证          从零起一条命令序列 + 期望看到什么
## 6. 已知问题            还没解决的，按证据排序
```

### `DEVLOG.md`（开发过程，可选但推荐）

按**轮次**记录，标题带日期，每轮写：现象 → 取证（命令与输出）→ 根因 → 修法 → 验证；
以及**被推翻的旧结论**（这条最有价值 —— 避免下一个人重走弯路）。

> 本机工作记录（`vm/` 目录）**不进版本库**。任何"想让后来人看到"的证据，最终都要落到
> 包内的 `README.md` / `DEVLOG.md` 里，别只留在 `vm/` 下当引用目标。

## 11. 检查清单

新包上线前过一遍：

- [ ] `python scripts\dpctl.py packs <名>` 全部就位，无 MD5 报错
- [ ] `up --pack <名>` 能开机，`screenshot` 看到该机型的 UI（不是控制台文字/黑屏）
- [ ] 画面**方向正确、满屏不斜切**
- [ ] `tap` 有反应；滑动/翻页可用（不是只能点一下）
- [ ] 进桌面后**不会**因低电量关机（该开 `battery` 的机型开了）
