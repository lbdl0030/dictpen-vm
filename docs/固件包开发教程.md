## 1. 三个概念

| 概念 | 是什么 | 放在哪 |
|------|--------|--------|
| **框架** | 虚拟机本身。只做通用的事：发现/校验包、组装 QEMU 启动、状态盘、传输/调试、显示前端 | `scripts/dpctl.py`、`scripts/packlib.py`、`scripts/initramfs-init.sh`、`vmgui/` |
| **runtime**（运行框架 / boot backend） | "这类固件怎么跑起来"：用哪个内核、镜像怎么挂、显示设备怎么给。一种固件形态一个 | `scripts/runtimes/*.py` |
| **固件包** | 一台机器的**全部会变的东西**：镜像、面板尺寸、补丁、开关 | `packs/<名字>/` |

规则只有两条：

1. **框架里不出现任何机型信息**（没有镜像名、没有分辨率常量、没有 HAL 名字）。
2. **包不依赖框架的某个具体实现**：它只声明"我要什么"（平台、面板、要覆盖哪些文件），
   框架要么满足，要么明确报错。

判断"我该改哪一层"：

- 换镜像、换分辨率、换补丁、改开关 → **写包**（不动代码）。
- 引导方式不同（不是 erofs + 通用内核，比如 OTA/安卓 A/B、或自家的内核）→ **加 runtime**。

## 2. 最快的上手方式

同族机器（RV1106 Linux 那一家）通常只要复制一个现成的包改路径：

```bat
:: 1. 复制（在资源管理器里复制也行）
xcopy /E /I packs\a6pro packs\mydev

:: 2. 把新机器的镜像放进 packs\mydev\images\，把 pack.toml 里的路径改掉
::    （name 也改成 mydev）

:: 3. 校验
python scripts\dpctl.py packs mydev
python scripts\dpctl.py up --pack mydev
```

如果 `packs mydev` 报"缺文件"或"MD5 不符"，按提示补文件/改 MD5 即可。
**先别急着删 a6pro 的补丁**——如果你不确定新机器要不要那只 HAL，见第 4、6 节。

## 3. 包目录与 pack.toml 全字段

```
packs/<名字>/
  pack.toml            # 元数据（下面逐条讲）
  images/              # 大文件：固件镜像。不进版本库（.gitignore 已排除）
  patches/             # 该机器"会变的东西"：HAL、logo、触摸桥、cfg 覆盖表…
  README.md            # 可选：来源/版本/校验/已知问题（强烈建议写）
```

`pack.toml` 完整示例（就是 a6pro 用的那份）：

```toml
name    = "a6pro"                              # 必须与目录名一致
note    = "A6pro / Pear_RV1106 / YoudaoOS 4.7.4"
version = "4.7.4"                              # 纯展示

[platform]                                     # 决定用哪个 runtime
soc     = "rv1106"                             # 纯展示（方便人看）
runtime = "rv1106-linux-erofs"                 # 框架里必须有这个名字
kernel  = ""                                   # 留空 = 用框架自带的通用内核
initrd  = ""                                   # 留空 = 用框架的通用 initramfs

[image]                                        # 路径相对**包目录**
rootfs = "images/a6-2-pro-ro-rootfs.img"       # 必需：挂给 guest 的只读根
boot   = "images/a6-2-pro-ro-boot_b.img"       # 可选：DTB/参数参考，框架不拿它启动

[display]                                      # 虚拟屏；EDID 由它生成
xres     = 560
yres     = 170
rotation = 0                                   # 目前只作为记录
bpp      = 32                                  # 目前只作为记录

[adapt]                                        # 适配开关：声明了才生效
logo        = "patches/logo.fb.gz"             # 开机画到 /dev/fb0
touchbridge = "patches/touchbridge.pl"         # 装并启动触摸桥
cfg_overlay = "patches/cfg.json.overrides"     # 只覆盖列出的 cfg.json 键
battery     = true                             # 伪造健康电量
license     = true                             # 开机写开发凭证（用框架自带脚本）
ap          = true                             # wlan1 上起虚拟热点
hooks       = ["patches/extra.sh"]             # 可选：包自带的开关机钩子

[adapt.replace]                                # 通用"覆盖 guest 文件"
"patches/libfalcon.so" = "/usr/lib/libfalcon.so"

[client]
profile = "pear-a6pro"                         # 交给 vmgui 的 profile 名

[state]
size_mb = 1024                                 # 可选：状态盘大小，留空 = 框架默认 512

[checks]                                       # 可选：启动前校验（不过就不让启动）
"images/a6-2-pro-ro-rootfs.img" = { md5 = "0dfe781b76955f5dfe3d8aedde585c36" }
```

字段规则：

- **所有路径都相对包目录**（也可以写绝对路径）。
- `[platform].kernel/initrd` 留空就用框架的（`tools/kernel-root-gui/boot/vmlinuz-*.img`
  + `images/initramfs.cpio.gz`）。只有当这个平台必须用**自己的内核**时才在这里指。
- `[display]` 必填 `xres/yres`：它一是给虚拟显示设备，二是给 guest 生成匹配的 EDID
  （框架不知道任何分辨率）。填错的表现是 UI 缩在角落 / 画面斜切。
- `[checks]` 是**硬校验**：对不上 `dpctl up` 直接拒绝启动（`dpctl packs <名>` 只提示）。
- `[client].profile` 是 `vmgui/profiles/<名>.toml` 的名字；找不到只会告警，不影响开机。
- `[state].size_mb` 是状态盘大小（MiB），留空 = 框架默认 512。**为什么这个值值得
  由包声明**：overlay 的 upper 层就住在状态盘上（`/state/upper`），盘一满，
  overlay 只能退化成只读（`overlayfs: ... (errno: 28)`），所有 S00 钩子都写不进
  `/mnt`，guest 侧整台机器表现为黑屏 + 服务反复重启。各机器的 `/userdata` 占用
  差别很大（a6pro 能塞进 512 MiB，a7pro 挤不进去），所以大小该跟机型一起走。
  改这个值要 `up --pack <名> --fresh` 才生效（已有的盘不会自动扩）。

## 4. patches：包能给 guest 做什么

`patches/` 里的东西不会自动生效——**都得在 `[adapt]` 里声明**。声明什么，框架做什么：

| 声明 | 框架会做 | 关键点 |
|------|----------|--------|
| `logo = <包内路径>` | 开机把文件 gunzip 到 `/dev/fb0`（早期一次 + rcS 后一次） | 文件是**原始 framebuffer 数据**（`bpp` 与面板一致的裸像素），不是 png/bmp |
| `touchbridge = <路径>` | 拷到 guest 的 `/root/.vm/`，装 `S00touchbridge` 启动它，并等设备节点出现 | 脚本必须自己创建 guest 要用的触摸设备节点（`cfg.json` 的 `tp` 指向它） |
| `cfg_overlay = <路径>` | 按文件里的 `key=value` **逐键**改 `cfg.json` | 见下 |
| `battery = true` | 装 `S00battery`：tmpfs 覆盖 `/sys/class/power_supply`，发布 80% 健康电量 | 机型电量栈不是这么读的，别开 |
| `license = true` | 装 `S00license`（写开发凭证）+ `S00sysinfo`（有 `DICTPEN_SN/UUID` 时写设备码）+ `S99license`（有设备码时换真凭证） | 用的是框架自带脚本，包里不用放 |
| `ap = true` | 装 `S00wifi-ap`：`wlan1` 起 hostapd（`Youdao-VM`）+ 转发/NAT | hostapd/iptables 二进制在框架的 initramfs 里 |
| `replace = {…}` | 开机把包里的文件覆盖到 guest 根的指定位置 | **键 = 包内路径，值 = guest 绝对路径** |
| `hooks = [...]` | 在 `switch_root` 前按文件名顺序 `source` 这些脚本 | 见下 |

### `cfg.json.overrides` 的格式

```ini
# 每行一个 key=value；空行和 # 开头忽略
width=560              # 值以数字开头 -> 按 JSON 数字替换 "width": <n>
direction=0
bpp=32
tp=/dev/input/by-path/axs_ts   # 值以 / 开头 -> 按 JSON 字符串替换 "tp": "<s>"
```

框架只改你列出的键，**其余一个字节都不动**（这是相对早期"整文件 sed"的关键改进）。
没列出的键保持固件原样——这正是"框架不污染别的机器"的落点。

### `hooks` 的执行环境

- 在 initramfs 的 `/init`（busybox sh）里、`switch_root` **之前**被 `source`。
- 因此：**用 POSIX sh**，不能用 guest 里的命令（要跑 guest 的二进制就
  `chroot "$TARGET" ...`）。
- 可用变量：`$TARGET` = guest 根（已挂好 overlay，可写）、`$OVERLAY`、`$STATE_OK`、
  `$INIT`，以及 `pack.env` 里的 `PACK/RUNTIME/PANEL/ADAPT_*`。
- 用途举例：往 `$TARGET/etc/init.d/` 里塞一个针对该机型的 rcS 钩子。

## 5. 包是怎么进到 guest 的

固件包里没有任何"会被框架永久装载"的东西。流程是**每次启动现拼一份 initrd**：

```
dpctl up --pack mydev
  ├─ packlib 读 packs/mydev/pack.toml，校验文件与 [checks] 的 MD5
  ├─ runtimes["rv1106-linux-erofs"] 组装 QEMU 平台参数（机器/内核/驱动/显示设备）
  ├─ packlib.ensure_initrd():
  │     框架通用 initramfs (images/initramfs.cpio.gz)
  │       + 包声明的 patches/**              -> /patches/**
  │       + 由 [display] 生成的 EDID          -> /lib/firmware/edid/pen.bin
  │       + pack.env（PACK/RUNTIME/PANEL/ADAPT_*） -> /pack/pack.env
  │       + [adapt].replace 的映射表          -> /patches/replace.list
  │     = vm/initrd-mydev.cpio.gz    （按"框架+包+runtime附加项"的哈希缓存，约 1 秒）
  ├─ QEMU 启动（状态盘 vm/state-mydev.img，显示走 -display none）
  └─ guest 里的 /init：挂 rootfs -> overlay -> state -> 读 /pack/pack.env
                       -> 只按包声明的开关做适配 -> switch_root
```

由此得到两条对你写包有用的推论：

- **换包/改包 = 重拼一份 initrd**，几秒钟的事，不需要重新构建框架的 initramfs。
- **没声明的键不会碰任何文件**；`/pack/pack.env` 不存在时，guest 侧所有机型适配全部
  按"关"处理（框架可以独立运行）。

> 框架的 `images/initramfs.cpio.gz` 只构建一次，永不含机型内容。要重新构建
> （改了 `initramfs-init.sh` 或模块列表后）：`python scripts\build-initramfs.py`。

## 6. 实战：做一个 RV1106 同族包

以"从 dictpen-rootfs 拿一台 Hermes 的固件"为例。

**第 1 步：拿镜像。** 从 release 下载 rootfs（erofs）和 boot（DTB）两个文件，
放进 `packs/hermes/images/`。

**第 2 步：算 MD5。** 把上游公布的值（或本地算的值，用于自校验）填进 `[checks]`：

```bat
certutil -hashfile packs\hermes\images\xxx-rootfs.img MD5
```

**第 3 步：写 pack.toml。** 从 a6pro 复制，至少改这些：

```toml
name    = "hermes"
note    = "Hermes / RV1106 / YoudaoOS x.y.z"
[platform]
soc     = "rv1106"
runtime = "rv1106-linux-erofs"       # 同族：一样
[image]
rootfs = "images/<你的 rootfs>"
boot   = "images/<你的 boot>"
[display]
xres = <?>                            # 面板尺寸：问真机 / 查 DTS / 看 cfg.json
yres = <?>
[client]
profile = ""                          # 没有专门 profile 就留空（只会告警）
```

**第 4 步：先不加任何补丁，试启动。**

```bat
python scripts\dpctl.py up --pack hermes --display none
python scripts\dpctl.py screenshot --out vm\hermes.png
```

盯这几处（都在串口日志里，`dpctl sh -c "..."` 或 `console.cmd` 都能看）：

| 关键字 | 含义 |
|--------|------|
| `### pack: hermes ... ###` | 包已生效 |
| `### erofs root mounted ###` | 镜像格式对（不是 erofs 会 `MOUNT FAILED`） |
| `mod: erofs ok` / `mod: overlay ok` | 框架模块加载正常 |
| `### state: ext4 created and mounted ###` | 状态盘就绪 |
| `### overlay: persistent upper ###` | 可写根就绪 |
| `### switch_root -> /mnt, init /sbin/init ###` | 真正交棒给固件 |

**第 5 步：按现象逐个加补丁。** 对照 a6pro 的经验：

| 现象 | 大概率要加 |
|------|-----------|
| 有画面但 UI 缩在角落 / 窗口尺寸不对 | `[display]` 的 `xres/yres` 填错了（EDID 由它生成） |
| 画面斜切/斜条 | `cfg_overlay`：`direction=0`（+ `width/height`） |
| 画面花、颜色不对 | `cfg_overlay`：`bpp=32` |
| 完全没有画面（停在启动图/黑屏） | `replace`：该机型打过补丁的显示 HAL |
| 进桌面约一分钟后自己关机 | `battery = true` |
| 点击没反应 | `touchbridge` + `cfg_overlay` 的 `tp=` 指向桥创建的设备 |
| 停在激活页 | `license = true` |
| 网络页里没有可连的热点 | `ap = true` |

**第 6 步：固化。** 把有效的开关写进 `pack.toml`，在 `packs/<名>/README.md` 里记下
来源、MD5、已知问题，然后：

```bat
python scripts\dpctl.py packs hermes     :: 明细 + MD5 核对
python scripts\dpctl.py up --pack hermes :: 正式启动
```

## 7. 实战：给异构平台写一个 runtime

什么时候需要：**引导方式和 RV1106 族不一样**。典型信号：

- 镜像不是 erofs（是 ext4 / sparse / OTA 包 / 安卓 A/B 分区）；
- 内核不是通用的（要用厂商内核 + 自己的 DTB）；
- 显示设备不能用 `bochs-display`；
- 厂商模块 `insmod` 报 `invalid module format`（说明和框架的通用内核不兼容）。

### 7.1 接口

`scripts/runtimes/__init__.py` 里定义了基类，**只需要实现这两个**：

```python
class Runtime:
    name = ""                 # 唯一名字，包的 [platform].runtime 写它
    note = ""                 # 一句话说明（给人看）

    def validate(self, pack):        # 返回 [问题描述]；空 = 没问题
        return []

    def kernel(self, pack):          # 这次启动用哪个内核
        return pack.kernel

    def initrd(self, pack):          # 基础 initramfs（通常用框架通用的）
        return pack.initrd

    def initramfs_extra(self, pack): # 额外要塞进 initrd 的东西（可选）
        return []                    # [(initrd 内路径, mode(含 0o100000), 数据, nlink)]

    def platform_args(self, pack, ctx):   # 组装 QEMU 的平台参数（必须实现）
        raise NotImplementedError
```

`ctx`（`BootContext`）由 dpctl 填好：

```python
BootContext(
    kernel    = ...,   # runtime.kernel(pack) 的结果
    initrd    = ...,   # merge 之后那份 vm/initrd-<包>.cpio.gz
    append    = ...,   # 内核 cmdline（框架通用部分；runtime 可以在自己返回前改它）
    state_img = ...,   # vm/state-<包>.img
)
```

`platform_args` 返回的这串参数后面，dpctl 会**追加**与机型无关的部分
（连接键盘/触摸板、user 网络、`-display`、monitor、QMP、两个串口）。所以你要给的
是"机器 + 内核 + 磁盘 + 显示设备"这一段就够了。

### 7.2 骨架

新建 `scripts/runtimes/my_platform.py`：

```python
"""runtime: my-platform —— <一句话说明这个平台>。"""
import os

from . import BootContext, Runtime, framework_initrd_default, framework_kernel_default


class MyPlatformRuntime(Runtime):
    name = "my-platform-erofs"
    note = "<这个平台怎么跑：镜像格式 / 内核来源 / 显示设备>"

    def validate(self, pack):
        problems = []
        if not pack.rootfs:
            problems.append("pack.toml 的 [image].rootfs 没写")
        if not pack.xres or not pack.yres:
            problems.append("pack.toml 的 [display] 缺 xres/yres")
        # 例：这个平台必须自带内核，缺了就报出来
        # if not pack.kernel:
        #     problems.append("该平台必须提供自己的内核（[platform].kernel）")
        return problems

    def kernel(self, pack):
        return pack.kernel or framework_kernel_default()

    def initrd(self, pack):
        return pack.initrd or framework_initrd_default()

    def initramfs_extra(self, pack):
        # 例：把该平台需要的额外文件塞进 initrd（路径尽量用 /patches/ 前缀）
        return []

    def platform_args(self, pack, ctx: BootContext):
        # 需要额外的内核参数就在这里改（BootContext 是可变对象）
        # ctx.append += " some.param=1"
        return ([
            "-M", "virt", "-cpu", "max", "-smp", "4", "-m", "2G",
            "-accel", "tcg,thread=multi",
            "-kernel", ctx.kernel, "-initrd", ctx.initrd, "-append", ctx.append,
        ]
            + self.drive_args(pack, ctx.state_img)   # 基类提供的两个 -drive
            + self.display_args(pack))               # 基类提供的 bochs-display
```

然后在 `scripts/runtimes/__init__.py` **文件末尾**的注册表里加上（必须在基类和
`framework_*_default` 定义之后，否则会循环导入）：

```python
from . import my_platform                                  # noqa: E402
from . import rv1106_linux                                 # noqa: E402

REGISTRY = {c.name: c for c in (
    rv1106_linux.Rv1106LinuxRuntime,
    my_platform.MyPlatformRuntime,
)}
```

### 7.3 然后呢

给新平台建一个包（`[platform].runtime = "my-platform-erofs"`），再：

```bat
python scripts\dpctl.py packs mydev      :: 应该能看到 runtime 而不是"未实现"
python scripts\dpctl.py up --pack mydev
```

现成的参考实现就是 `scripts/runtimes/rv1106_linux.py`（60 行左右）。
`packs/s7pro/` 是一个**故意不提供 runtime** 的例子：它在框架里跑不起来，
但框架会明确说"该平台 runtime 未实现"，而**不会**拿别的机型的补丁去覆盖它。

> 平台差异研究（厂商内核、模块、面板）是这件事的大头；框架侧只需要上面这一个文件。

## 8. 调试与自检

### 8.1 看 guest 到底套用了什么

```bat
python scripts\dpctl.py sh -c "cat /proc/cmdline"
python scripts\dpctl.py sh -c "dmesg | head -80"            :: 引导早期的 pack/mod/state 行
python scripts\dpctl.py screenshot --out vm\s.png --zoom 2
```

串口日志（每次开机重写）在 `vm/serial.log`；QEMU 自身输出在 `vm/qemu.log`。
适配钩子都会往内核日志里写自己的结果，常用关键字：

```
S00replace: <文件> -> <guest 路径> rc=0
S00license: dev license written (174 bytes)
S00battery: fake pack published (capacity 80%)
S00touchbridge: touch device ready
S00wifi-ap: uplink NAT ready (...)
S99logo: boot logo painted
pack hook: <钩子名>
cfg.json: applied N override(s) from the pack
```

### 8.2 改坏了 /userdata 怎么办

```bat
python scripts\dpctl.py down
python scripts\dpctl.py up --pack mydev --rescue     :: 不进笔的 UI，串口给 root shell
:: 串口里干活，或干脆 --fresh 重来
```

`--rescue` 下没有 SSH/adb，只能用串口（`console.cmd` 或 `dpctl sh --serial`）。

### 8.3 改了框架的 initramfs 之后

```bat
python scripts\build-initramfs.py                    :: 重新打包通用 initramfs
bash -n scripts\initramfs-init.sh                    :: 顺手语法检查（busybox sh 容忍度低）
python scripts\dpctl.py up --pack mydev              :: 下次启动会自动重拼 initrd
```

### 8.4 包的 import/export 自检

```bat
python scripts\dpctl.py pack export mydev -o dist\mydev.dpm
python scripts\dpctl.py pack import dist\mydev.dpm --force
python scripts\dpctl.py packs mydev                  :: 文件就位 + MD5 通过
```

## 9. 分发

- **整包搬运用** `dpctl pack export/import`（单个 `.dpm` = tar.gz，含镜像和补丁）。
  镜像版权归网易有道：只在自己机器之间搬，是否外传由你决定。
- **可传播的代码包**（`scripts/package.py`）只带包里的**描述性文件**
  （`pack.toml` / `README.md` / `cfg.json.overrides` / `touchbridge.pl`），
  不带 `images/` 与 `.so` 之类的固件派生物；自检里对 `*.so`、`*.img` 是硬拦截。
  如果你给新包加了解释性文件，想让它对收包的人可见，就在
  `scripts/package.py` 的 `PACK_FILES` 里加上文件名。

## 11. 常见坑

**"该平台 runtime 未实现"**
包的 `[platform].runtime` 拼错，或者平台确实还没支持。`dpctl packs <名>` 会打印框架
现有的 runtime 名字。

**改了 pack.toml 但启动结果没变**
initrd 是按哈希缓存的；如果改的是包内**文件内容**而哈希没变（理论上不会），
删掉 `vm/initrd-<包名>.cpio.gz*` 再启动即可。

**`[checks]` 对不上导致不让启动**
这是有意的硬校验。上游重新发过包就更新 MD5；本地镜像损坏就重新下载。

**同族机器照抄 a6pro 的 `replace`（HAL）结果反而崩了**
那只 HAL 是针对特定固件版本打的补丁。不同机型/版本**不要**照抄，
先用原版镜像试启动，确认"必须换 HAL"再加。

**多个包共用一个状态盘**
框架已经按包分盘（`vm/state-<包名>.img`），不要手工把它们指向同一个文件——
不同机型的 `/userdata` 目录结构可能互相冲突。

**开机全黑，串口里一片 `Read-only file system` / `No space left on device`**
状态盘满了。overlay 的 upper 层在盘上，盘满时 overlay 只能只读挂载，于是
`/mnt` 上所有写入（装 S00 钩子、写 cfg.json、放补丁）全部失败，笔的 UI 起不来。
判断依据是串口里那条 `overlayfs: failed to create directory /state/work/work
(errno: 28)`。解法两个：把 `[state].size_mb` 调大再 `up --fresh`；框架的 `/init`
也会在 overlay 之前自动清厂商 swap 文件（`/userdisk/swap/swap.file`，实测 257 MiB
而 VM 内存够 2 GiB，`/proc/swaps` 里 Used=0）。**不要**去删 `/userdisk/secondary`，
那是 miniapp 解压二级应用的真实路径。

**面板尺寸不知道填多少**
从真机的 `/etc/miniapp/resources/cfg.json` 的 `width/height` 取，
或看 DTS / 显示屏规格。填错的两个典型后果：UI 缩在角落、或窗口比例不对。

**画面全黑，但串口日志一切正常**

先按 `dpctl screenshot` 出来的 PNG **字节数**分类，再查对应那条：

| 字节数 | 含义 | 查哪条 |
|--------|------|--------|
| ≈ 400（640×172 全 0） | **一个字都没画** | (a) 加载链断了 |
| 几十~一百多 KB，但内容被裁或大片黑 | **画了，版式不对** | (b) 机型/主题选错 |

*（a）完全没画。* 先排除"还没画完"（开机前两分钟是控制台文字，桌面约 2 分钟），
然后看两个计数：

```bat
python scripts\dpctl.py sh -c "grep -c 'could not load module' /data/applog/DictPen_*.log"
python scripts\dpctl.py sh -c "grep -c 'launchApp fail'      /data/applog/DictPen_*.log"
```

非 0 就说明框架的 JS/jsapi 链断在加载阶段。a7pro 实测的根因是**包的
`patches/runDictPen.sh` 替代厂商 `/usr/bin/runDictPen` 时把 `LD_LIBRARY_PATH` 写少了**
（注释写着"与厂商原版一致"，其实不一致）：

```sh
# 厂商原版 —— 替代脚本必须逐字核对这一段
export LD_LIBRARY_PATH=$APP_PATH/libs:$LD_LIBRARY_PATH:/etc/miniapp/jsapis:/etc/miniapp/messageknife
```

少了 `/etc/miniapp/messageknife`，`/etc/miniapp/jsapis/libjsapi_export_core.so` 的
DT_NEEDED `libgetdevicename.so` 就找不到（该文件其实就在 `messageknife/` 里），
uClibc 的 `dlopen` 失败——`dlerror()` 的字面量就是 `File not found`，日志里表现为
`ERROR:File not found:dlopen in dynamic_load_jsapi`（格式串是 `ERROR:%s:dlopen in …`，
`%s` = `dlerror()`）。于是 `global` 这个 jsapi 加载不了 → `globalManager-*.js` /
`navgationbarManger-*.js` / `app.js` 接连失败 → `$falcon.launchApp` 抛
`TypeError: not a function` → 框架退回启动「验证引导」(8080282888534774)，
而它不画东西 → 全黑。

排查"加载链断了"的三板斧：

1. **和一个能出画面的同族包对照**（同参数起 a6pro），diff 上面两个计数和其它关键字
   ——本次 a6pro 两项都是 0、第二个启动的 app 直接是 HOME（8080222437664451）。
2. **查依赖是否齐全**：把可疑 `.so` 的 DT_NEEDED 全列出来，逐个在 guest 的
   `/lib`、`/usr/lib`、`/oem/YoudaoDictPen/output/libs`、`/etc/miniapp/messageknife`
   里查存在性，缺哪个一目了然。
3. **看运行中进程的真实环境**：`ps | grep '[m]iniapp'` 拿 pid，再
   `tr '\0' '\n' < /proc/<pid>/environ | grep LD_LIBRARY_PATH`。
   想快速验证改法，不必重启 VM：`killall -9 guardian_run miniapp` 之后用正确路径
   手工起一份 `/usr/bin/miniapp`，几秒就能截图看结果。

*（b）画了但版式不对。* 机型码来自 vendor storage（`/dev/vendor_storage`），VM 里
没有这个设备 → 主题查表 miss → 回退到固件里的常量 `MOCK_THEME = "theme-melon"`，
而 melon 是按 **960×266** 排版的 → 1:1 画进 640×172 就被裁（实测：把 960×266 的
渲染裁左上角与 640×172 的截图逐像素比，差异 0%）。

固件自己留了后门：`YSettingManagerPrivate::themeName()` 第一件事就是
`YEnvironment::value("MOCK_THEME", "")`，**返回值非空就直接当主题名**，不再查表。
所以在包的 `runDictPen.sh` 里钉一行即可：

```sh
export MOCK_THEME=theme-y09   # 本机对应的主题；机型↔主题表在 libyddal_business_core.so 的字符串池里
```

验证：`/userdata/miniapp/resources/env.json` 应变成 `640 / 172 / theme-y09`，
日志里 `loadRootPage themeName= theme-y09`，桌面完整。想更彻底（让机型真被识别）
就得伪造 vendor storage：`rkvendor_read(id=0xE, buf, 0x400)` 返回 ASCII
`<前缀>_<机型>_SKU_<区域>_<硬件档>`（`Y09` → serial `0x1e` → 机型表索引 `0x1e` =
`YDPA7-1`）。注意往 `/userdata/cfg/sys_config.conf` 写 `sku=` **没用**——应用启动
就把它抹成空。

> 一句话判据：`screenshot` **400 B = 没画**（查 (a)），**~100 KB = 桌面**（还被裁查 (b)）。
> a7pro 的完整取证见 `vm/_a7pro-verify/FINDINGS.md` 与 `packs/a7pro/README.md`。

**`hooks` 里用了 guest 才有的命令**
`hooks` 跑在 initramfs 的 shell 里（switch_root 之前）。要用 guest 的命令就
`chroot "$TARGET" <命令>`。
