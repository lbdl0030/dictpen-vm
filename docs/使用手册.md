## 1. 这是什么

用 QEMU 跑**词典笔的真实固件**，得到一个能开机、能点、能传文件、能用 adb 调试的
"实机"。当前唯一验证过的机型是 **A6pro**（YoudaoOS 4.7.4）。

两条设计原则，看后面的内容时会反复用到：

- **虚拟机是框架，固件是可拆卸的包。** 框架里没有任何机型信息；一台机器的镜像、
  面板尺寸、显示补丁都装在一个**固件包**（`packs/<名字>/`）里，启动时选一个。
- **不改变固件。** 笔的软件栈（falcon/UI、wpa_supplicant、bluetoothd…）原样运行，
  缺的硬件用等效的虚拟硬件顶替（见第 9 节）。

## 2. 环境要求

| 需要 | 说明 |
|------|------|
| Windows 10/11 | 不需要管理员权限，不需要 WSL |
| Python 3.11+ | 跑 `dpctl` / `bootstrap` / `package`（只用标准库） |
| Python 3.11–3.13 + PySide6 | 跑默认显示前端 vmgui（3.13 最稳）；没有就自动回退 QEMU 自带的 GTK 窗口 |
| 磁盘 | 约 6 GB（QEMU 工具链 3 GB + 内核 + 固件包 1.6 GB + 状态盘 0.5 GB） |
| 网络 | 只在"重建环境/下载固件"时需要 |

> 硬件加速不可用：Windows 的 WHPX 不支持 ARM64 客户机，只能纯软件模拟（TCG）。
> 速度慢是正常的，**开机到桌面约 2 分钟**。

## 3. 第一次使用

### 3.1 重建依赖

收到代码包的人，先跑一次：

```bat
python scripts\bootstrap.py --check   :: 只看缺什么，不动任何文件
python scripts\bootstrap.py           :: 能自动的自动拉取/构建，其余给出指引
```

它会按 `deps/manifest.toml` 依次处理：zstd → 便携 QEMU（MSYS2）→ busybox → 通用内核
→ 虚拟热点用的 arm64 依赖 → 生成 SSH 密钥（收紧权限）→ 生成 mitm 自签证书 →
构建框架通用 initramfs。每步"已有就跳过"，可以反复跑。

### 3.2 拿到固件包

固件镜像版权归网易有道，**不在代码包里**，需要自行下载：

```bat
python scripts\bootstrap.py --check          :: 缺固件时会打印下载指引（含上游文件名与 MD5）
```

把下到的文件放进对应包的 `images/` 目录，再确认：

```bat
python scripts\dpctl.py packs                :: 列出所有包，标出文件是否就位
python scripts\dpctl.py packs a6pro          :: 该包的明细 + MD5 核对
```

如果你是从别人那里拿到**整包**（`.dpm` 文件），直接导入即可：

```bat
python scripts\dpctl.py pack import a6pro.dpm
```

### 3.3 启动

```bat
python scripts\dpctl.py up --pack a6pro
```

出现窗口后，等它开机（首次开机会先格式化状态盘）。想确认真的起来了：

```bat
python scripts\dpctl.py wait --adb
```

> 开机过程中屏幕上先是**控制台文字**（倾斜/压缩是正常的，那是内核 console 在小屏上的
> 显示），大约 2 分钟后有道桌面（查词翻译 / 语音助手 / 随身听）才画出来。别急着判断
> "没画面"。

## 4. 选择固件包并启动

```bat
python scripts\dpctl.py packs                       :: 有哪些包、镜像是否就位
python scripts\dpctl.py up --pack a6pro             :: 用 a6pro 启动
python scripts\dpctl.py up                          :: 只装了一个包时可以省 --pack
python scripts\dpctl.py up --pack a6pro --fresh     :: 清空该包的持久化数据重来
```

`up` 的常用开关：

| 开关 | 作用 |
|------|------|
| `--display vmgui` | 默认。画面交给仓库里的 vmgui（QEMU 自身 `-display none`，画面/输入走 QMP） |
| `--display gtk` | 回退到 QEMU 自带窗口（vmgui 不可用时自动回退到这个） |
| `--display none` / `--headless` | 完全不开窗口（配合 `screenshot` 看画面） |
| `--rescue` | 救援模式：不启动笔的 UI，串口直接给 root shell，用来修坏掉的 `/userdata` |
| `--dev` | 保留 miniapp launcher（默认会被禁用，见 README） |
| `--no-license` | 开机不写开发凭证（会停在激活页，用来观察激活流程） |
| `--no-pointer` | GTK 窗口下不显示触控反馈指针 |

启动前 `up` 会替你检查：镜像在不在、`[checks]` 的 MD5 对不对、该平台框架支不支持。
任一项不过就直接告诉你原因，不会让 QEMU 报一堆看不懂的错。

```bat
python scripts\dpctl.py up --pack s7pro
:: dpctl: 包 s7pro 声明的 该平台 runtime 未实现：'cv18xx-linux-erofs'；框架现有：rv1106-linux-erofs
```

## 5. 看画面与操作

### 5.1 vmgui（默认前端）

- 窗口大小按**实际帧尺寸**自适应，不做任何分辨率假设；开机时从 640×480 切到笔屏
  尺寸是**原地重建**，不闪、不丢焦点。
- 默认 `fit` 模式 + `nearest` 缩放（笔屏像素少，平滑会糊）。
- 画布内有触摸反馈环，所以 vmgui 下**不需要** `dpctl pointer`。
- 快捷键：`F11` 全屏、`Ctrl+Alt+S` 截图、`Ctrl+Alt+R` 重置视图、
  `Ctrl+Alt+P` 设置面板、`Ctrl+Alt+Q` 退出、`Ctrl+Alt+G` 切换鼠标捕获。

单独启动（VM 已在跑时可以直接连上去）：

```bat
py -3.13 -m vmgui --profile pear-a6pro     :: profile 名由固件包的 [client].profile 给出
py -3.13 -m vmgui --print-config           :: 打印生效配置 + 每个键的来源
py -3.13 -m vmgui --list-profiles
```

### 5.2 截图与点击（不需要窗口）

```bat
python scripts\dpctl.py screenshot --out vm\screen.png --zoom 2
python scripts\dpctl.py tap 280 85         :: 在笔屏坐标 (280,85) 注入一次触摸
```

- 截图默认裁剪到**当前固件包声明的面板尺寸**；`tap` 也按同一尺寸换算坐标。
- `--w/--h` 可以手动指定，不指定就用包里的。
- **`tap` 和 vmgui 抢同一个 QMP 连接**：vmgui 在前台时 `tap` 会连不上——
  先关掉 vmgui 窗口，或干脆用 `--display none` 启动。

### 5.3 实时查看窗口（GTK 风格）

```bat
python scripts\dpctl.py view --zoom 2      :: 一个按笔屏尺寸定大小的窗口，实时刷新
```

### 5.4 触控反馈指针（仅 GTK 窗口）

笔屏是触摸 UI，没有 hover。GTK 窗口下按 `up` 会**自动调出**一个透明、可点穿、
不抢焦点的置顶覆盖层，在鼠标位置画一个圈（按下变红变大）：

```bat
python scripts\dpctl.py pointer      :: 手动调出
python scripts\dpctl.py nopointer    :: 收掉
```

### 5.5 词典笔控制台（推荐日常使用）

```bat
python scripts\dpctl.py console     :: 或双击 vm-console.cmd
```

控制台把设备画面、状态栏和常用操作放在一个窗口里：

- 工具条：`启动` / `快速启动` / `保存快照` / `关机` / `重启` / `截图` /
  `左上角返回` / `Home` / `音量－` / `音量＋`（音量键仅 x6pro，其余按包灰显）；
  `F11` 全屏，`Esc` 退出全屏，
  `Tab` 收/开右侧抽屉。
- 快速启动：先关机，按「保存快照」把当前状态保存为快照（无音频，约 1.5–2 分钟）；
  之后「快速启动」约 6 秒恢复首页。快照与普通状态盘互相独立，快照运行期间的改动
  下次恢复会丢弃；要声音请用普通「启动」冷启动。
- 抽屉：串口、guest 应用、命令、文件、配置、蓝牙、声音。声音页读写客机侧的 QEMU USB Audio
  （客机音量/静音），页面上常驻提示宿主输出设备的静音/音量；选另一个操作会中断仍在执行的
  那一条。a6pro/a7pro 固件只有 tinyalsa，播放 48 kHz 立体声 WAV。
- 「配置」页的扩容只改 VM 状态盘（客机 `df` 会变）；x6pro、x7、a6pro、x5pro、s6pro、s7pro 的设置页
  已由 preload shim 改成读 VM 状态盘，扩容后会跟着变（「空间清理」「关于→存储容量」都跟随）；
  其他机型逐步适配。实际数字看「配置」页的宿主/客机两格。
- 「设备」下拉切换目标机型；虚拟机运行中切换会先请求关机，且只切换目标、不自动启动。

## 6. 进系统、传文件、调试

| 命令 | 作用 |
|------|------|
| `dpctl shell` | 交互式实机命令行（SSH，root） |
| `dpctl sh -c "uname -a"` | 跑一条命令，回传**真实退出码** |
| `dpctl put a.txt /userdata/a.txt` | 传文件进实机（优先 adb push，其次 SSH） |
| `dpctl get /userdata/a.txt a.txt` | 取文件到电脑 |
| `dpctl adb shell` | 电脑端 adb（自动拉起 guest 的 adbd 并 connect） |
| `dpctl adb logcat` | 其它 adb 子命令直接透传 |
| `dpctl status` | VM / 端口 / adb / 当前包 / 状态盘 |
| `dpctl down` | 关机 |

细节：

- SSH 没起来时 `sh/put/get` 会**自动回落到串口**，所以开机过程中也能用；但那时输出
  里可能混着控制台的历史日志（正常现象）。
- `dpctl sh` 的退出码就是实机里命令的退出码，例如 `dpctl sh -c "exit 7"` 返回 7。
- `dpctl wait --timeout 300 [--adb]`：等实机 shell（并可选地等 adb）就绪。

## 7. 端口

| 用途 | 宿主机 | 客机 |
|------|--------|------|
| SSH（dropbear） | 127.0.0.1:2222 | 22 |
| ADB（adbd） | 127.0.0.1:15037 | 5555 |
| 串口控制台 | 127.0.0.1:4444 | — |
| QEMU 监视器（截图用） | 127.0.0.1:4445 | — |
| QMP（vmgui / tap 用） | 127.0.0.1:4446 | — |
| 蓝牙 HCI（hci_uart） | 127.0.0.1:4447 | /dev/ttyAMA1 |

ADB 宿主端口特意避开 adb 的模拟器探测区间（5554–5585），免得 `adb devices` 里冒出
重复的 `emulator-XXXX`。

### 7.1 自己接 SSH 客户端（VSCode / Termius / 裸 ssh / `ssh-vm.cmd`）

**所有固件包共用 127.0.0.1:2222，而每个型号的 dropbear 主机密钥各不相同**（`up --fresh`
重建状态盘也会换一把），所以换包后很容易撞见

```
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!
Offending RSA key in NUL:1
Password authentication is disabled to avoid man-in-the-middle attacks.
```

`NUL` 这个出处就是本项目的历史坑：以前 `dpctl` 和 `ssh-vm.cmd` 都写
`-o UserKnownHostsFile=NUL`，而 **Git-Bash/MSYS 的 ssh 不认 Windows 的空设备名**，
会在当前工作目录**建一个真文件叫 `NUL`** 当 known_hosts。旧型号的密钥冻在里面，
之后每个包都"主机密钥变了" —— 更糟的是 ssh 会因此**禁用密码与键盘交互认证**，
依赖口令的客户端直接连不上。注意 `StrictHostKeyChecking=no` 只是"照样放行"，
挡不住这段警告。

现在统一改成一份真实文件 `vm\known_hosts_devvm`，并由 `dpctl up` 每次开机清空
（每次启动本来就是一把新密钥），`dpctl`、`ssh-vm.cmd` 与你的 `~/.ssh/config`
三处指向同一个文件，不会再互相顶。自己配客户端时写进 `~/.ssh/config`
（下文两处 `<仓库根目录>` 换成本仓库所在目录；这里**不要**给 `Host 127.0.0.1` 配 `Port`，否则 `ssh 127.0.0.1` 的 22 端口也会被带到
2222 去；OpenSSH 10.5 也不支持 `Match port`，只能按地址匹配）：

```
Host devvm
    HostName 127.0.0.1
    Port 2222
    User root
    IdentityFile <仓库根目录>/tools/ssh/id_devvm
    IdentitiesOnly yes
    StrictHostKeyChecking no
    UserKnownHostsFile <仓库根目录>/vm/known_hosts_devvm

Host 127.0.0.1 localhost
    User root
    IdentityFile <仓库根目录>/tools/ssh/id_devvm
    StrictHostKeyChecking no
    UserKnownHostsFile <仓库根目录>/vm/known_hosts_devvm
```

配完 `ssh devvm`、`ssh -p 2222 root@127.0.0.1`、`ssh-vm.cmd` 都直接可用；已经写坏的
全局条目用 `ssh-keygen -R "[127.0.0.1]:2222"` 清掉（原文件留成 `known_hosts.old`），
仓库根目录若躺着 `NUL` 也一并删。代价是回环口不再做主机密钥校验 —— 威胁面只有
"本机另有进程冒充 127.0.0.1:2222"，对开发虚拟机是可接受的。

还有一条排查经验：`dpctl sh` 只回传 stdout，**ssh 的警告全在 stderr 里被吞掉**，
所以"`dpctl sh` 正常"不能当作 ssh 通道健康的证据；要裸跑一次 `ssh` 看完整输出，
或用 `ssh -G` 查生效选项。

**双击 `ssh-vm.cmd`** 走的是另一套环境：用的是**系统 PATH**（`ssh` 解析成
`C:\Windows\System32\OpenSSH\ssh.exe`，没装 OpenSSH 客户端就没有），而且脚本一旦不
`pause`，报错会随窗口关闭一起消失，看着就像"双击没反应"。现在它会先 `where ssh` 预检，
失败时打印退出码和排查顺序再停住等按键：

| 窗口里看到 | 意思 |
|------------|------|
| `no ssh in PATH` | 没装 Windows 的 OpenSSH 客户端可选功能，或在 Git Bash 里跑 |
| `Connection refused`（退出码 255） | 虚拟机没在跑，或刚 `up` 完 dropbear 还没起 —— 先 `run-vm.cmd`，再 `python scripts\dpctl.py wait` |
| `Permission denied` | 用错密钥，本脚本固定用 `tools\ssh\id_devvm` |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | `vm\known_hosts_devvm` 是旧的，`dpctl up` 会清 |
| `PTY allocation request failed on channel 0`（退出码 255） | 客机没挂 `devpts`，dropbear 拒绝一切**要终端**的登录 —— 见下面那段 |

**"带命令能连"不等于"ssh 能用"**。`dpctl sh`、initramfs 钩子这类调用都是"给一条命令、
拿一段输出"，不需要伪终端；而**双击 `ssh-vm.cmd`、`dpctl shell`、VSCode、Termius 是交互式
登录，会请求 PTY**。固件自己的 userspace 从不分配伪终端，所以它的启动序列里根本没有挂
`devpts` 这一步 —— 表现就是密钥、端口、主机密钥全对，窗口里却只有那一句 PTY 失败。
框架已在 `scripts/initramfs-init.sh` 里挂上（`mount --move /dev` 会连子挂载一起搬进真根，
所以 7 个包一处修完）。如果你手上的 base initramfs 是旧的，重打一次即可：

```bat
python scripts\build-initramfs.py    :: 改过 initramfs-init.sh 必须重打
python scripts\dpctl.py down && python scripts\dpctl.py up --pack <name>
```

判断依据：登进去 `tty` 给出 `/dev/pts/N` 就是好的；`grep pts /proc/mounts` 为空就是没挂。

脚本本体保持纯 ASCII：cmd.exe 按 OEM 代码页读 `.cmd`，写中文不仅乱码，还会把 `echo`
行拆成"命令"执行。


串口控制台也可以单独用：

```bat
console.cmd                        :: Ctrl+] 退出
python scripts\console.py -c "uname -a"
python scripts\console.py -f cmds.txt     :: 批量执行，回传真实退出码
```

## 8. 持久化：改动会不会丢

改动落在第二块 virtio 盘上，**每个固件包一份**（`vm/state-<包名>.img`，不同机型不会
互相串味），重启保留：

- `/`（根文件系统）的修改走 overlay 的 upper 层；
- `/userdata`、`/userdisk` 直接持久（`/data` 是指向 `/userdata` 的软链）；
- 首次开机由实机自带工具格式化这块盘（所以要等一会儿）；
- 万一状态盘不可用，会自动退化为内存盘：机器照常开机，只是改动重启就没了。

```bat
python scripts\dpctl.py status       :: 看当前包的盘有多大
python scripts\dpctl.py up --fresh   :: 删掉当前包的盘，下次开机重新格式化
```

## 9. 虚拟出来的硬件

真机的无线是 SDIO 组合芯片，QEMU 里没有，于是用等效硬件顶替，**笔里的软件栈原样跑**：

| 能力 | 怎么做的 | 怎么验证 |
|------|----------|----------|
| 显示 | `bochs-display` 提供线性显存 framebuffer（guest 写完即上屏，与真机 LCD 语义一致） | 桌面上屏、`dpctl screenshot` 有画面 |
| 触摸 | virtio-tablet 的鼠标事件经 uinput 桥重发布成 `axs_ts` 触摸屏（笔只认 `BTN_TOUCH`） | 鼠标点击驱动 UI；`dpctl tap` 有效 |
| Wi-Fi 网卡 | `mac80211_hwsim` 造出 `wlan0`，笔自带的 `wpa_supplicant -Dnl80211` + `wifi-manager` 照常接管 | 设置里能开关、扫描 |
| 可连的热点 | `wlan1` 上跑一份 arm64 hostapd，SSID `Youdao-VM`（开放网络），并做转发+NAT | 扫描能看到 `Youdao-VM`，关联后 `wpa_state=COMPLETED` |
| 蓝牙 | 第二个串口接宿主上的虚拟 HCI 控制器，guest 用 `btattach` 得到 `hci0`；控制台开关的是客机 hci0，不是电脑蓝牙 | `ls /sys/class/bluetooth` 有 `hci0`；BlueZ 可上电；真实设备需 USB 蓝牙直通 |
| 电池 | tmpfs 覆盖 `/sys/class/power_supply`，发布一份健康电量（80%） | 不会在一分钟后"低电量关机" |
| 声音 | `qemu-xhci` + `usb-audio` 接宿主 `dsound`；声卡数量由包的 `[audio].cards` 决定。这个数不是固定的 2，要覆盖厂商 `asound.conf` 里 speaker/数字耳机别名的最大卡号（s6pro 要 4，x5pro 要 5，x7/x6pro 是 2） | `dpctl audio-check` 通过只证明某张卡能放；应用内播放要另验（x6pro ~60%、x7 74.4%、s6pro 85.3%） |
| 崩溃日志 | 开机把 `/userdisk/corefile` 裁到最新 500 个，并常驻一个 janitor 每 10 分钟再裁 | 状态盘不会被几万个日志文件顶满 |

**声音自检**（改完后最先跑这个）：

```bash
python -X utf8 scripts/dpctl.py audio-check
```

它会先读宿主默认播放设备的静音/音量，再让客机放 5 遍 48 kHz 测试音，用 Core Audio 的
端点峰值判定声音是否真的到达扬声器。三个常见失败：

- `静音 True` / `音量 0%`：宿主这边被静音，命令会直接给出取消静音的修复行；
- `客机里没有 tinyplay/aplay`：该包的最小根文件系统缺播放器，换一台或用包里自带的；
- `峰值 < 1%`：链路断了，按提示看客机 `/tmp/vm-audio-check.log` 与 `/proc/asound/cards`。

`audio-check` 通过**不代表应用内播放通过**：它只往某一张卡放测试音，而厂商 HAL 会按
固定卡号/ALSA 别名（如 s6pro 的 `hw:2,0`、x7 的 `tc_digital`）打开设备。应用内无声时，
先看 SoundPlayer 日志里的设备名与 `[audio].cards` 是否覆盖了它（见
`docs/固件能力盘点.md` §12.13–§12.15）。

另外，客机空闲一段时间会自己关机（应用侧的息屏/关机逻辑），`audio-check` 因此可能报
"虚拟机没在跑"；重新 `dpctl up` 即可。

想关掉热点：启动时加内核参数 `DICTPEN_AP=0`（或让包不开 `[adapt].ap`）。

## 10. 激活与凭证

真机开箱要激活：拿**设备码**去有道服务器换一份凭证（`/userdata/cfg/license`，174 字节）。
VM 里没有设备码（`system_info.bin` 里缺序列号/UUID），所以：

- **默认**：开机钩子写一份**开发凭证**，直接跳过激活页进桌面；
- **会真实验签的那几台**（a7pro 4.13.0、x7 4.8.7、s7pro 4.23.0）光有开发凭证不够：开机约
  5 分钟后应用会重新校验并失败，前台被切到「开始激活」，还会把凭证删掉。这几台由包内的
  `verifyLicense` 恒真补丁兜住，配方与判据见 [疑难排查](疑难排查.md) §5.2；
- 想观察激活流程：`dpctl up --no-license`，会停在激活页；
- 手里有**已注册设备**的 `system_info.bin`：把它放到 `/userdata/cfg/` 再重启，
  钩子会去服务器换真凭证：

```bat
python scripts\dpctl.py put <你设备的>\system_info.bin /userdata/cfg/system_info.bin
python scripts\dpctl.py down
python scripts\dpctl.py up --pack a6pro
```

也可以手工触发一次真凭证恢复（会打印卡在哪一步）：

```bat
python scripts\dpctl.py license
```

离线看激活请求长什么样：guest 的 `/etc/hosts` 把 `fanyidan.youdao.com` 指到 `10.0.2.2`，
宿主上跑 `python scripts\mitm-verify.py`（自签证书在 `vm/mitm/`）。
⚠️ 劫持期间**查词功能会失败**（同一个域名），用完记得把那行删掉。

## 11. 关闭与清理

```bat
python scripts\dpctl.py down          :: 关机（会先请 guest poweroff，超时再杀进程）
python scripts\dpctl.py status        :: 确认已停
```

`down` 会一并收掉虚拟蓝牙控制器、指针覆盖层和 vmgui。就算 VM 是用 `run-vm.cmd` 起的，
`dpctl` 也能识别并关掉。

清理空间：

| 想清掉 | 删什么 |
|--------|--------|
| 只清运行状态 | `vm/state-<包名>.img`（下次开机重新格式化） |
| 清日志/截图/pid | `vm/` 下的 `*.log`、`*.png`、`*.pid` |
| 全部依赖（要重新 bootstrap） | `tools/` |

## 12. 常见问题

**画面全黑（先按截图的字节数分类，这决定了查哪条线）**

```bat
python scripts\dpctl.py screenshot --out vm\s.png
dir vm\s.png
```

- **约 400 字节** = 一个字都没画。先等够 2 分钟（开机前两分钟屏幕上是控制台文字，
  桌面要 ~2 分钟才画出来），然后依次看：

  ```bat
  python scripts\dpctl.py sh -c "ps | grep miniapp"
  python scripts\dpctl.py sh -c "grep -c 'could not load module' /data/applog/DictPen_*.log"
  python scripts\dpctl.py sh -c "grep -c 'launchApp fail'      /data/applog/DictPen_*.log"
  ```

  后两个计数只要非 0，就是"应用的 JS/jsapi 没加载起来"。最常见的原因是**当前包的
  `runDictPen` 替代脚本把 `LD_LIBRARY_PATH` 写少了**——少了 `/etc/miniapp/jsapis`
  和 `/etc/miniapp/messageknife` 这两段，`libgetdevicename.so` 找不到、`dlopen`
  失败，于是 `global` 模块加载不了，一个页面都渲染不出来（全黑）。判据与修法见
  [`docs/疑难排查.md`](疑难排查.md) §0（截图字节数与判据分类）与 §1。
- **几十~一百多 KB，但内容不对**（右侧/下侧被裁、大片黑）= 画出来了，但**机型没
  识别出来、主题回退**到了别的机型的皮肤。看
  `/userdata/miniapp/resources/env.json` 里的 `theme` 与
  `currentScreenWidth/currentScreenHeight`，正常应与包声明的面板一致
  （a7pro 正常是 `theme-y09` / 640×172）。修法同样见教程 §11。

串口日志（`vm/serial.log`）里搜 `S00replace` 可以确认包的文件替换有没有生效。

**一直停在"开始激活"**
`/userdata/cfg/license` 不存在。检查是不是用了 `--no-license`。

**开机约一分钟后自己关机（提示低电量）**
电量没被伪造成功：`dpctl sh -c "cat /sys/class/power_supply/battery/capacity"` 应是 80。
不是 80 说明当前包的 `[adapt].battery` 没开，或者 initramfs 不是最新的。

**点击没反应**
先看是不是状态盘满了：`dpctl sh -c "ls /userdisk/corefile | wc -l"`（正常在 500 以内）。
堆满了就 `dpctl down` → `dpctl up --pack <名> --rescue` → 删掉 `/userdisk/corefile/*`
→ 正常启动。另外 vmgui 在前台时 `dpctl tap` 会因为抢不到 QMP 而失败，先关窗口
（QEMU 的一个 QMP chardev 只服务一个客户端；`dpctl screenshot` 走 HMP 4445，不受影响，
所以"截图正常但 tap 失败"是占用，不是 VM 挂了）。

**截图全黑 / 窗口没反应**（QEMU 侧先排除）
确认用的是 `bochs-display`（框架默认），且 `dpctl sh -c "ls /dev/fb0"` 存在。
这两样都正常的话，就属于上面「画面全黑」里的两种应用侧问题。

**画面斜切/斜条**
当前包的 `cfg.json` 覆盖没生效（`direction` 不是 0）。看串口日志里的
`cfg.json: applied N override(s) from the pack`。

**PySide6 装不上 / vmgui 起不来**
PySide6 目前要求 Python < 3.15。装一个 3.13 再 `py -3.13 -m pip install PySide6`；
或者用 `DICTPEN_VMGUI_PYTHON` 指定解释器；再不行 `--display gtk` 用 QEMU 自带窗口。

**adb 连不上**
`dpctl status` 先确认 VM 在跑，然后直接用 `dpctl adb`（它会自动在 guest 里拉起 adbd
并 connect）。还不行看 `dpctl sh -c "cat /tmp/adbd.log"`。

**SSH 报 `UNPROTECTED PRIVATE KEY FILE`**
私钥权限太宽。`bootstrap.py` 会自动用 `icacls` 收紧；若手工生成过，重新跑一次
`bootstrap.py --only ssh-key`。

**"没有固件包"**
`packs/` 下没有包。下载固件放进 `packs/<名字>/images/`，或 `dpctl pack import <文件>`。

**报"该平台 runtime 未实现"**
这个包声明的平台框架还不支持（例如 S7pro 的 CV1826）。这不是配置错误——
要么换支持的平台，要么按 [`docs/固件包开发教程.md`](固件包开发教程.md) §7 给它写一个 runtime。

**改动重启后丢了**
`dpctl status` 看 `state:` 那一行有没有当前包的状态盘；看串口日志里有没有
`### state: ext4 mounted ###` 和 `### overlay: persistent upper ###`。
有 `state: unavailable ...` 说明格式化/挂载失败（会自动回落内存盘，不影响开机）。
