# 发布说明：dictpen-vm `1.0.0-preview`

> 有道词典笔实机固件在 PC 上的模拟开发环境。**框架不含任何固件**：一台机器会变的东西
> 全部收在 `packs/<名字>/` 这个"可拆卸固件包"里，启动时用 `--pack` 选一台。
>
> **镜像不进本包**（版权归网易有道）。请按第 2 节从固件库下载，再按第 3 节放进对应目录。
> 本包内**包含**固件包里的适配文件（打过补丁的 HAL、触摸桥、x6pro 的合成器载荷等），
> 所以镜像到位后即可开跑。

## 1. 这个版本里有什么

- 框架：`scripts/`（`dpctl` 命令面、包管理、可插拔 boot backend）、`vmgui/`（显示前端）、
  `docs/`（四份文档）、`deps/`（外部依赖清单）。
- 七个固件包：`packs/{a6pro, a7pro, s6pro, s7pro, x5pro, x6pro, x7}/` —— 各自带
  `pack.toml` + `patches/`；`images/` 为空，等你去下载。
- 文档入口：先看 [`README.md`](../README.md)（门面 + 60 秒上手 + 文档地图），
  再按角色选：[`docs/使用手册.md`](../docs/使用手册.md)（只想用起来）、
  [`docs/固件包开发教程.md`](../docs/固件包开发教程.md)（要加一台机器）、
  [`docs/插件模型.md`](../docs/插件模型.md)（要改框架/写插件）、
  [`docs/疑难排查.md`](../docs/疑难排查.md)（卡住了按现象查）。

各包当前能力见各自的 `README.md` / `DEVLOG.md`；总览见 `README.md` 的"已验证能力"。

## 2. 装起来（三步）

```bat
:: 1) 解压本包（就是这份仓库的快照）
:: 2) 按第 3 节下载镜像，放进各自的 packs\<名字>\images\
:: 3) 重建依赖（QEMU / 内核 / 工具链），然后选一台机器启动
python scripts\bootstrap.py
python scripts\dpctl.py packs                    :: 先看七个包的就位情况
python scripts\dpctl.py up --pack a6pro          :: 或 s6pro / x5pro / x6pro …
```

`python scripts\dpctl.py packs <名字>` 会**逐文件核对 MD5**：缺文件或拿错版本都会指出来
（`[checks]` 是硬校验，对不上 `up` 会拒绝启动）。

## 3. 镜像下载与命名（重点）

**从哪里下**：固件镜像是独立发布的，在
<https://github.com/lbdl0030/dictpen-rootfs/releases>。

**放到哪、叫什么名**：文件名必须和 `pack.toml` 里写的一致（否则 `packs` 报"缺文件"）。
下表左边是**目标文件名**，右边是**上游资产名**：

| 包 | 放进 `packs/<包>/images/` 的文件名 | 上游资产名 | 备注 |
|---|---|---|---|
| a6pro | `a6-2-pro-ro-rootfs.img`、`a6-2-pro-ro-boot_b.img` | 同名 | 直接放 |
| a7pro | `a7-1-pro-ro-rootfs_b.img`、`a7-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| s6pro | `S6-1-pro-ro-system_b.img`、`S6-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| s7pro | `S7-1-pro-ro-system.img`、`S7-1-pro-ro-boot.img` | `S7-1-pro-ro-system_b.img`、`S7-1-pro-ro-boot_b.img` | ⚠ **要去掉结尾的 `_b`** |
| x5pro | `x5-1-pro-ro-rootfs_b.img`、`x5-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| x6pro | `system_a.img`、`boot_a.img` | — | ⚠ **本版镜像不在固件库**（那里只有 `x6-2-plus-ota.img`，是 X6-plus 的 OTA 单包）。需自行从 X6pro 的 OTA 包提取，见 `packs/x6pro/DEVLOG.md` |
| x7 | `x7-system_a.img` | — | ⚠ 同上，X7 那个 tag 目前只有说明文件 |

> **`b` 与 A/B 分区**：带 `_b` 的是 A/B 双分区机型的镜像。本框架**只读挂载**其中一份，
> 所以 s7pro 那份可以直接改名后用。

**`bootstrap.py` 会自动下载吗？** 会，但目前 `deps/manifest.toml` 只覆盖 a6pro，
且里面写的"上游文件名"已经过时（那是更早的发布名）。**所以第一次请按上表手工下载**；
之后帮忙补全 `manifest.toml` 就能一条命令搞定。

## 4. 第一次运行

```bat
python scripts\dpctl.py up --pack <名字>          :: 默认拉起 vmgui 显示窗口
python scripts\dpctl.py screenshot --out vm\x.png :: 不想开窗口时截图（HMP，不占 QMP）
python scripts\dpctl.py tap 480 240               :: 注入一次点击（注意：vmgui 在跑时 QMP 被它占着）
python scripts\dpctl.py down                      :: 关机
```

判断"到底起没起来"最快的办法是看 `screenshot` 出来的 PNG **字节数**：
≈400 B = 一个字都没画；几十~一百多 KB = 画了但版式不对；100 KB 以上 = 桌面。
详细判据与 46 条常见现象见 [`docs/疑难排查.md`](../docs/疑难排查.md)。

## 5. 已知问题（挑三条最容易踩的）

1. **Windows 上脚本可能被转成 CRLF，导致机器再也起不来** —— 症状是内核 panic 循环
   `Attempted to kill init!`，panic 前一行是某个包钩子的 `syntax error: unexpected word`。
   仓库已加 `.gitattributes` 根治；若你自己改过脚本，别用会加 CR 的编辑器。
   详见 [`docs/疑难排查.md`](../docs/疑难排查.md) §8.6。
2. **x6pro 首次开机要等约 6 分钟**，期间画面停在固件自带的"正在初始化配置，请等待…"
   属正常（35 个预设包在纯软件模拟下逐个解包）。别当成卡死。
3. **注入点击前先关掉 vmgui**：QEMU 的一个 QMP 通道只服务一个客户端，vmgui 默认占着它，
   `dpctl tap` 会报连接被拒。用 `--display none` 重启即可。
