# 发布说明：dictpen-vm `1.1.0`

> 有道词典笔实机固件在 PC 上的模拟开发环境。**框架不含任何固件**：一台机器会变的东西
> 全部收在 `packs/<名字>/` 这个"可拆卸固件包"里，启动时用 `--pack` 选一台。
>
> **镜像不进本包**（版权归网易有道）。请按第 3 节下载并放进对应目录。
> 本包内**包含**固件包里的适配文件（打过补丁的 HAL、触摸桥、x6pro 的合成器载荷等），
> 所以镜像到位后即可开跑。发布资产：`dictpen-vm-1.1.0.zip`（约 90 MB）。

## 0. 本次更新（相对 1.0.0，2026-10-21）

- **控制台**：`vm-console.cmd` / `dpctl console` 新增设备下拉切换、F11 全屏、
  空态写明当前目标；抽屉补齐蓝牙/声音页；声音输出走 QEMU usb-audio → 宿主 dsound，
  声音页读写客机音量/静音，并常驻提示宿主输出设备。
- **蓝牙页**：明确操作的是**客机内虚拟蓝牙**（不是电脑蓝牙）；扫描改用有界
  `btmgmt --timeout 8 find`（不再被 `bluetoothctl`/D-Bus 挂住），「连接」禁灰并注明
  真实设备需要 USB 蓝牙直通。
- **存储页**：x6pro 设置显示 `-1GB` 已修（补 `/dev/block/by-name`）；并用 preload
  shim 让设置页读 VM 状态盘——2G 显示 0.4GB/2GB，扩到 3G 后显示 0.4GB/3GB（跟随）。
  s7pro（ELF32 armhf）用同思路的 armhf shim + NMT no-op，6G 盘下「空间清理」与
  「关于→存储容量」都显示 1.8GB/6GB；s6pro（armhf + glibc 2.23）同样处理，8G 盘下
  两条入口都显示 0.5GB/8GB（并把应用商店自动升级钉回固件预设 2.1.1，否则存储/关于
  页在 2.1.6 上缺模块全黑）；x5pro 复用同款 shim，1G 盘下两条入口显示 0.4GB/1GB；a6pro（uClibc）用
  libc-free shim（raw statfs + operator new）并把 NMT 补丁钉掉，1G 盘显示 0.3GB/1GB；
  x7（AArch64）复用 x6 shim，8G 盘显示 1.3GB/8GB；其他机型待逐台适配。
- **声音页**：选中其他操作会直接中断仍在执行的那条命令（不再卡在「上一条命令尚未返回」）；
  无声时先查宿主输出设备——本次根因是 `扬声器 (Senary Audio)` 被静音在 9%，
  客机→QEMU 已用 wav 后端抓到真实 440 Hz。
- **实体键**：Home 在 x6pro / s6pro / s7pro / x5pro / a6pro / a7pro 可用（x6pro 的
  `init failed res== -14` 已定位为 `/proc/device-tree/model` 映射不到机型，用模型 bind
  修复）；音量±仅 x6pro；x7 的固件没有对应按键节。控制台工具条按包点亮/灰显。
- **快速启动**：`dpctl fast save` 保存首页快照，`dpctl up --fast` / 控制台「快速启动」
  约 6 s 恢复；快照不含音频，普通「启动」仍保留声音。
- **启动性能**：冷启动约 55–62 s（x6pro 实测；TCG 模拟，CPU/内存调整无实质收益）。
- **文案与文档**：用户可见文案统一为陈述式；README、使用手册、疑难排查与各包
  README 同步更新；单测 217 项通过。详见 README「已验证能力」与各包 README。

- 文档入口：先看 [`README.md`](../README.md)（门面 + 60 秒上手 + 文档地图），
  再按角色选：[`docs/使用手册.md`](../docs/使用手册.md)（只想用起来）、

## 2. 装起来（四步）

```bat
:: 1) 解压本包（就是这份仓库的快照）
:: 2) 按第 3 节下载镜像，放进各自的 packs\<名字>\images\
:: 3) 重建依赖（QEMU / 内核 / 工具链），并装控制台依赖
python scripts\bootstrap.py
python -m pip install PySide6                    :: 控制台需要；只用 dpctl 可跳过
:: 4) 打开控制台，选一台机器
python scripts\dpctl.py packs                    :: 先看七个包的就位情况
vm-console.cmd                                   :: 图形控制台（也可 dpctl up --pack a6pro）
```

`python scripts\dpctl.py packs <名字>` 会**逐文件核对 MD5**：缺文件或拿错版本都会指出来
（`[checks]` 是硬校验，对不上 `up` 会拒绝启动）。PySide6 目前要求 Python < 3.15，
建议用 3.13（见 [`使用手册.md`](使用手册.md) §2）。

## 3. 镜像下载与命名（重点）

**从哪里下**：固件镜像是独立发布的，在
<https://github.com/lbdl0030/dictpen-rootfs/releases>。

**放到哪、叫什么名**：文件名必须和 `pack.toml` 里写的一致（否则 `packs` 报"缺文件"）。
下表左边是**目标文件名**，右边是**上游资产名**：

| 包 | 放进 `packs/<包>/images/` 的文件名 | 上游资产名 | 备注 |
|---|---|---|---|
| a6pro | `a6-2-pro-ro-rootfs.img`、`a6-2-pro-ro-boot_b.img` | 同名 | 直接放 |
| a7pro | `a7-1-pro-ro-rootfs_b.img`、`a7-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| s6pro | `S6-1-pro-ro-system_b.img`、`S6-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| s7pro | `S7-1-pro-ro-system.img`、`S7-1-pro-ro-boot.img` | `S7-1-pro-ro-system_b.img`、`S7-1-pro-ro-boot_b.img` | ⚠ **要去掉结尾的 `_b`** |
| x5pro | `x5-1-pro-ro-rootfs_b.img`、`x5-1-pro-ro-boot_b.img` | 同名 | 直接放 |
| x6pro | `system_a.img`、`boot_a.img` | — | ⚠ **本版镜像不在固件库**（那里只有 `x6-2-plus-ota.img`，是 X6-plus 的 OTA 单包）。需自行从 X6pro 的 OTA 包提取，见 `packs/x6pro/DEVLOG.md` |
| x7 | `x7-system_a.img` | — | ⚠ 同上，X7 那个 tag 目前只有说明文件 |

> **`b` 与 A/B 分区**：带 `_b` 的是 A/B 双分区机型的镜像。本框架**只读挂载**其中一份，
> 所以 s7pro 那份可以直接改名后用。

**其实可以不用手工下**：`deps/manifest.toml` 已经为**每一台有上游镜像的机器**写好条目
（a6pro / a7pro / s6pro / s7pro / x5pro），下载与改名都由它负责 ——

```bat
python scripts\bootstrap.py --check               :: 先看缺哪些（只检查，不动文件）
python scripts\bootstrap.py --only firmware-x5pro  :: 只取你用的那一台（都标了 optional）
python scripts\bootstrap.py                       :: 或一次把想要的都取齐
```

`bootstrap.py` 会按上游资产名下载，落盘时**改成 vm 规范名**（上表左边那列，也就是
`s7pro` 要去掉 `_b` 这件事，它替你做了）。上表保留下来是给**手工下载**或**核对**时用的。
x6pro / x7 上游暂时没有镜像，仍需自行准备。

## 4. 第一次运行

```bat
python scripts\dpctl.py up --pack <名字>          :: 默认拉起 vmgui 显示窗口
vm-console.cmd --pack <名字>                      :: 或者用图形控制台（画面 + 状态 + 抽屉）
python scripts\dpctl.py fast save --pack <名字>   :: 关机后保存首页快照（约 1.5–2 分钟）
python scripts\dpctl.py up --fast --pack <名字>   :: 之后约 6 s 回首页（无音频）
python scripts\dpctl.py screenshot --out vm\x.png :: 不想开窗口时截图（HMP，不占 QMP）
python scripts\dpctl.py tap 480 240               :: 注入一次点击（注意：vmgui 在跑时 QMP 被它占着）
python scripts\dpctl.py down                      :: 关机
```

判断"到底起没起来"最快的办法是看 `screenshot` 出来的 PNG **字节数**：
≈400 B = 一个字都没画；几十~一百多 KB = 画了但版式不对；100 KB 以上 = 桌面。
详细判据与 46 条常见现象见 [`docs/疑难排查.md`](../docs/疑难排查.md)。

## 5. 已知问题（挑三条最容易踩的）

1. **Windows 上脚本可能被转成 CRLF，导致机器再也起不来** —— 症状是内核 panic 循环
   `Attempted to kill init!`，panic 前一行是某个包钩子的 `syntax error: unexpected word`。
   仓库已加 `.gitattributes` 根治；若你自己改过脚本，别用会加 CR 的编辑器。
   详见 [`docs/疑难排查.md`](../docs/疑难排查.md) §8.6。
2. **x6pro 首次开机要等约 6 分钟**，期间画面停在固件自带的"正在初始化配置，请等待…"
   属正常（35 个预设包在纯软件模拟下逐个解包）。别当成卡死。后续可用
   `dpctl fast save` + `up --fast` 在约 6 s 内恢复首页（快照无音频）。
3. **注入点击前先关掉 vmgui**：QEMU 的一个 QMP 通道只服务一个客户端，vmgui 默认占着它，
   `dpctl tap` 会报连接被拒。用 `--display none` 重启即可。
4. **控制台需要 PySide6；快速启动没有声音**：没有 PySide6 时 `vm-console.cmd` 会给出安装提示；
   `up --fast` 恢复的快照不含 usb-audio，要声音请用普通「启动」冷启动。保存快照前必须先关机。
   另外，听不到先查 Windows 默认输出设备是否静音或音量为 0（本次实测 `扬声器 (Senary Audio)`
   被静音在 9%）；控制台声音页有常驻提示。

## 7. 从 1.0.0 升级

直接解压覆盖即可，`packs/*/images/` 保持不动。已有状态盘可以继续使用；快速启动快照是
1.1.0 新增的，需要重新 `dpctl fast save`。实体键修复烘在新的 initrd 里，首次启动会自动重建。
