# 插件模型：框架是宿主，机器是插件

> **这份文档回答一件事：想改点什么，该落到哪个"插件点"。**
> 操作步骤（我要加一台机器）看 [`docs/固件包开发教程.md`](固件包开发教程.md)；
> 机型个案与排查看 [`docs/疑难排查.md`](疑难排查.md)。
>
> **接口契约只写在本文件**，其它文档只引用、不复制 —— 否则又会回到"两份文档各说一套"。

---

## 1. 宿主与四个插件点

框架（宿主）本身**不认识任何一台机器**：代码里没有镜像名、分辨率常量、HAL 名字。
一台机器会变的东西全部落在四个插件点里，宿主只提供"装载与执行"。

```
                    ┌──────────────── 宿主（脚本 + 通用资产）────────────────┐
                    │ scripts/dpctl.py    启动/停止/截图/点击/传文件/调试    │
                    │ scripts/packlib.py  读包、校验、把包并进本次 initrd    │
                    │ scripts/initramfs-init.sh  guest 侧通用 init          │
                    │ vmgui/              显示前端；tools/ 通用内核与 initramfs│
                    └───────────────────────────────────────────────────────┘
                              ▲          ▲            ▲             ▲
              ①固件包 packs/<名字>/  ②runtime scripts/runtimes/*.py
              ③guest 适配 patches/**  ④显示与输入 profile / EDID / 桥
```

| 插件点 | 是什么 | 放在哪 | 什么时候动它 |
|---|---|---|---|
| ① **固件包** | 一台机器"会变的东西"的总声明 | `packs/<名字>/pack.toml`（+`images/`+`patches/`） | 换机型 |
| ② **引导 runtime** | "这类固件怎么跑起来"的 boot backend | `scripts/runtimes/<名字>.py` | 换引导方式（镜像格式/内核/显示设备变了） |
| ③ **guest 适配** | 让固件在本 VM 里正常起来的具体动作 | 包内 `patches/**` | 画面/触摸/服务/首启出问题 |
| ④ **显示与输入** | 虚拟屏尺寸、前端 profile、DRM 兼容、触摸桥 | `[display]` / `[client]` / 包内 HAL 与桥脚本 | 画面尺寸、旋转、点不动 |

三条贯穿全局的规则：

1. **宿主零机型**：宿主代码里不出现具体机器的镜像名、分辨率、HAL 名。
2. **包只声明需求**：包说"我要覆盖哪些文件、开哪些开关"，由宿主执行；包不 import 宿主代码。
3. **没声明就不动**：包没写的键，宿主一个字节都不碰 guest 的文件。

## 2. 决策树：我要改 X，动哪个点

```
现象 / 需求                                       → 动哪个插件点
─────────────────────────────────────────────────────────────────────────
换一台机器的镜像                                  → ①（新建包）
面板尺寸/分辨率不对（UI 缩在角落、被裁）           → ④（[display]）+ 包内 cfg 覆盖
画面斜切 / 上下颠倒                               → ④（cfg 的 direction / tp_direction）
完全没有画面（停在启动图或黑屏）                   → ③（先看 `docs/疑难排查.md` §1：多半是加载链或 HAL）
点不动 / 只能点一下                              → ④（触控桥）+ ③（cfg 的 tp）
进桌面后自己关机 / 说没插电                        → ③（battery 开关）
停在激活/登录页                                  → ③（license 开关）
应用说"需要联网"但其实网是通的                      → ③（包内钩子模拟厂商芯片节点）
首启卡在"正在初始化配置"                          → ③（等待时长；见 `docs/疑难排查.md` §4）
镜像不是 erofs/ext4、要用厂商内核、显示设备不通用   → ②（写一个 runtime）
厂商合成器/显示栈依赖专有硬件（Mali/RGA…）         → ③（包内整包换合成器）＋ ②（若无从下手）
要对外分发包里的某份说明文件                       → ①（`[dist].include`）
```

## 3. 插件点①：固件包

### 3.1 目录形状

```
packs/<名字>/
  pack.toml      # 唯一必需文件；name 必须等于目录名
  images/        # 固件镜像（大文件，.gitignore 已排除，需自行下载）
  patches/       # 该机器"会变的东西"：HAL、logo、桥脚本、cfg 覆盖表、钩子素材…
  README.md      # 开箱信息（来源/版本/MD5/能力现状/已知问题）—— 建议写
  DEVLOG.md      # 可选：按轮次记根因、取证与纠正（开发过程）
```

### 3.2 字段契约表

| 段 / 键 | 类型 | 缺省 | 语义 | 校验时机 |
|---|---|---|---|---|
| `name` | str | — | **必须**等于目录名 | 解析即用 |
| `note` / `version` | str | `""` | 纯展示 | 展示 |
| `[platform].soc` | str | `""` | 纯展示（给人看） | 展示 |
| `[platform].runtime` | str | `""` | 选哪个引导插件；必须存在于宿主注册表 | `packs <名>` / `up` 时查表 |
| `[platform].kernel` | 路径 | `""` | 留空 = 宿主通用内核 | 缺文件 → 拒绝启动 |
| `[platform].initrd` | 路径 | `""` | 留空 = 宿主通用 initramfs | 同上 |
| `[image].rootfs` | 路径 | — | **必需**：只读根镜像 | 缺文件 → 拒绝启动 |
| `[image].boot` | 路径 | `""` | 仅作参数参考，宿主不拿它启动 | 缺文件 → 拒绝启动 |
| `[display].xres/yres` | int | `0` | 虚拟屏物理尺寸；**EDID 由它生成** | 缺 → runtime 报"面板尺寸必需" |
| `[display].rotation` / `bpp` | int | `0` | 目前只作记录 | — |
| `[adapt].logo` | 路径 | — | 开机画到 `/dev/fb0` 的**裸像素**（gunzip 后），不是 png | 缺文件 → 报错 |
| `[adapt].touchbridge` | 路径 | — | 装并启动 uinput 触摸桥 | 缺 → 报错 |
| `[adapt].cfg_overlay` | 路径 | — | 只覆盖文件里列出的 `cfg.json` 键 | 缺 → 报错 |
| `[adapt].battery` | bool | `false` | 伪造健康电量（仅 `ADAPT_BATTERY=1` 时生效） | — |
| `[adapt].license` | bool | `false` | 装框架自带的开发凭证钩子 | — |
| `[adapt].ap` | bool | `false` | `wlan1` 上起虚拟热点 + NAT | — |
| `[adapt].hooks` | [路径] | — | 包自带脚本，switch_root 前逐个 source | 缺 → 报错 |
| `[adapt].extra` | [路径] | — | 素材树：原样进 `/patches/<相对路径>`（目录递归、单文件按 basename 平铺） | 缺 → 报错 |
| `[adapt.replace]` | {包内路径: guest 绝对路径} | — | 通用"覆盖 guest 文件"，宿主只按表搬运、不解释内容 | 缺 → 报错 |
| `[client].profile` | str | `""` | 交给 vmgui 的 profile 名 | **找不到只告警**，不影响开机 |
| `[state].size_mb` | int | `0`=宿主默认 | 状态盘大小；overlay 的 upper 就住这块盘 | **只在创建盘时生效** |
| `[checks]` | {路径: md5} 或 `路径 = "md5"` | — | 硬校验，对不上**拒绝启动**（`packs` 只提示） | 每次启动 |
| `[dist].include` | [包内相对路径] | — | 追加"可对外分发"的文件（见 §7.3） | 打包自检 |

> 路径都相对**包目录**（也可写绝对路径）。

### 3.3 失败表现

| 情况 | 表现 |
|---|---|
| `runtime` 拼错 / 未实现 | `up` 报"该平台 runtime 未实现：… 框架现有：…" |
| 缺 `rootfs` / patches 文件 | `packs <名>` 列 `[缺失]`；`up` 拒绝启动 |
| `[checks]` 对不上 | 同上（这是有意的硬校验） |
| `[client].profile` 找不到 | 只告警，照常开机 |

## 4. 插件点②：引导 runtime

### 4.1 接口

`scripts/runtimes/__init__.py` 定义基类 `Runtime`。宿主只依赖这几个方法：

```python
class Runtime:
    name = ""      # 唯一名字；包的 [platform].runtime 写它
    note = ""      # 一句话说明（给人看）

    def validate(self, pack) -> list[str]:      # 这个包为什么跑不了；空 = 没问题
    def kernel(self, pack) -> str:              # 本次启动用哪个内核
    def initrd(self, pack) -> str:              # 基础 initramfs（通常用宿主通用的）
    def initramfs_extra(self, pack) -> list:    # 额外要并进 initrd 的东西
                                                # [(initrd 内路径, mode(含 0o100000), data, nlink)]
    def platform_args(self, pack, ctx) -> list[str]:   # 组装 QEMU 的平台参数（必须实现）
```

基类还提供两件通用工具，直接复用、不要各写一遍：

```python
self.display_args(pack)          # -> ["-device", "bochs-display,xres=…,yres=…"]（尺寸来自包）
self.drive_args(pack, state_img) # -> 只读 rootfs + 可写状态盘两条 -drive
```

`ctx`（`BootContext`）由宿主填好：`kernel` / `initrd`（已合并的 `vm/initrd-<包>.cpio.gz`）/
`append`（内核 cmdline；runtime 可以就地追加）/ `state_img`。

### 4.2 注册：自动发现（不必改宿主文件）

**加一个平台 = 往 `scripts/runtimes/` 丢一个 `.py` + 建一个包**，不用回来改
`runtimes/__init__.py`：宿主会扫这个目录、import 每个非 `_` 开头的模块、把其中的
`Runtime` 子类全部收进注册表（递归找子类的子类；重名或缺 `name` 会在 `dpctl packs` 里报出来）。

因此有三条**契约**：

1. runtime 模块的**顶层只做定义、不做副作用** —— 发现过程会 import 它；
2. 试验/半成品请用 `_` 开头命名（如 `_my_platform.py`），发现过程会跳过；
3. 单个模块 import 失败不会拖垮宿主，问题会收集起来由 `dpctl packs` 打出来。

### 4.3 生命周期（一次 `up` 里 runtime 被调用的顺序）

```
packlib 读 pack.toml，跑 validate(pack)        → 有问题就拒绝启动
runtime.kernel(pack) / runtime.initrd(pack)     → 决定内核与基础 initramfs
packlib.ensure_initrd(...)                      → 拼 vm/initrd-<包>.cpio.gz（含 runtime.initramfs_extra）
runtime.platform_args(pack, ctx)                → 平台那一段 QEMU 参数
宿主追加通用参数                                 → 输入设备、user 网络、-display、monitor、QMP、串口
```

也就是说：**runtime 只负责"机器 + 内核 + 磁盘 + 显示设备"这一段**，其余不用管。

### 4.4 现有的四个 runtime

| name | 用于 | 差异要点 |
|---|---|---|
| `rv1106-linux-erofs` | a6pro / a7pro / x7 | erofs 只读根 + 通用内核 + bochs-display |
| `cv18xx-linux-ext4` | s6pro / x5pro | 原始 ext4 根（校验 superblock magic `0x53ef`） |
| `cv18xx-linux-erofs` | s7pro | 同族但根是 erofs |
| `rockchip-linux-ext4` | x6pro | 原始 ext4 根；用户态是 aarch64 + glibc，厂商合成器依赖 Mali/RGA（包内换软件合成器） |

## 5. 插件点③：guest 适配

包能对 guest 做的改动分两条通路：**声明式**（宿主按语义执行）与**命令式**（包自带脚本自己干）。
能用声明式就用声明式 —— 宿主会替你把"时机"和"只改列出的键"这些纪律兜住。

### 5.1 声明式（在 `[adapt]` 里声明）

| 声明 | 宿主会做 | 关键点 |
|---|---|---|
| `logo` | 开机把文件 gunzip 到 `/dev/fb0`（早期一次、rcS 后一次） | 是**裸 framebuffer 像素**，`bpp` 要与面板一致 |
| `touchbridge` | 拷到 guest `/root/.vm/`，装 `S00touchbridge` 并等设备节点出现 | 脚本要自己创建 `cfg.json` 的 `tp` 指向的节点 |
| `cfg_overlay` | 按 `key=value` **逐键**改 `cfg.json` | 只改列出的键，其余一个字节不动 |
| `battery` | tmpfs 覆盖 `/sys/class/power_supply`，发布 80% 健康电量 | 电量栈不是这么读的机型别开 |
| `license` | 装框架自带的 `S00license`/`S00sysinfo`/`S99license` | 脚本是宿主通用资产，包里不用放 |
| `ap` | `wlan1` 起 hostapd + 转发/NAT | hostapd/iptables 在宿主 initramfs 里 |

### 5.2 命令式

| 手段 | 语义 | 典型用途 |
|---|---|---|
| `[adapt].hooks` | switch_root **之前**、在 `/init` 的 shell 里按文件名顺序 `source` | 停用厂商 init、装自己的 rcS 脚本、改 fstab、seed `/userdata`、模拟字符设备 |
| `[adapt].replace` | 把包内文件**覆盖**到 guest 根的指定绝对路径 | 换 HAL/启动脚本/固件内的 `.so`；**也常用来投送 `.tar` 载荷** |
| `[adapt].extra` | 把包内的**目录树原样**放进 `/patches/`，给 hooks 当素材 | 备用的 Debian 二进制树、`strace`/`dropbear`、perl 运行时 |

`hooks` 的执行环境（写之前先记住）：

- 跑在 initramfs 的 busybox sh 里，**switch_root 之前** —— 所以只能用 POSIX sh 与 initramfs 里的
  命令；要跑 guest 的命令得 `chroot "$TARGET" …`。
- 可用变量：`$TARGET`（guest 根，已挂好 overlay、可写）、`$OVERLAY`、`$STATE_OK`、`$INIT`，
  以及 `pack.env` 里的 `PACK` / `RUNTIME` / `PANEL` / `ADAPT_*`。
- 目录里没有别的钩子时也要能独立工作（别人的包不该依赖你的包）。

### 5.3 guest 侧执行顺序（宿主真实顺序）

```
initramfs /init
  1. mount proc / sysfs / devtmpfs / devpts
  2. 建/挂状态盘（ext4），失败时退回 tmpfs(只读根，仅能救援)
  3. 挂只读根 -> $TARGET；overlay(lower=只读根, upper=状态盘)
  4. 读 /pack/pack.env        -> PACK / RUNTIME / PANEL / ADAPT_*（没有包时全部按"关"）
  5. license 钩子             <- 仅当包开了 license 且 /patches/restore_license.sh 在
  6. cfg.json 覆盖            <- 仅当 /patches/cfg.json.overrides 在
  7. touchbridge              <- 仅当 /patches/touchbridge.pl 在
  8. battery                  <- 仅当 ADAPT_BATTERY=1
  9. corefile 整理与常驻清理
 10. wifi 热点 + NAT          <- 仅当 ADAPT_AP=1
 11. 蓝牙虚拟控制器
 12. [adapt].replace         <- 按 /patches/replace.list 搬运
 13. logo 投送/绘制           <- 仅当 /patches/logo.fb.gz 在
 14. **包自带 hooks**         <- /patches/hooks/ 按文件名排序逐个 source（最后一步）
 15. switch_root -> 固件自己的 /sbin/init
```

要点：**包自带 hooks 排在第 14 步**，也就是框架的所有适配都做完之后。所以钩子要"改框架刚装好的东西"（例如再覆盖一次 cfg）是安全的。

### 5.4 `/pack/pack.env` 的键

由宿主按包声明生成，guest 侧 init 读它来决定开关：

| 键 | 值 | 来源 |
|---|---|---|
| `PACK` | 包名 | `name` |
| `RUNTIME` | runtime 名 | `[platform].runtime` |
| `VERSION` | 版本 | `version` |
| `PANEL` | `宽x高` | `[display]` |
| `ADAPT_BATTERY` / `ADAPT_LICENSE` / `ADAPT_AP` | `1` | 对应开关为真时才有这一行 |

### 5.5 失败表现

| 情况 | 表现 |
|---|---|
| 忘了在 `[adapt]` 里声明 | 文件进不了 guest（`/patches/` 里没有它），钩子不会装 |
| 状态盘满 | overlay 退化成只读 → guest 里所有写入失败 → 黑屏 + 服务反复重启；串口有 `errno: 28` |
| 改完架构代码忘重打 initramfs | 改动"看起来没生效"。改了 `scripts/initramfs-init.sh` 必须 `python scripts\build-initramfs.py` |

## 6. 插件点④：显示与输入

### 6.1 虚拟屏与 EDID

- 虚拟显示设备由 runtime 的 `display_args()` 给出（现役是 `bochs-display`，尺寸取 `[display]`）。
- **EDID 由 `[display]` 的宽高现算**（`packlib.build_edid`），作为 `/lib/firmware/edid/pen.bin`
  并进 initrd，内核 cmdline 用 `drm_kms_helper.edid_firmware=Virtual-1:edid/pen.bin`。
  异形尺寸的单个 timing 会被内核当 BAD 剔除，所以同一尺寸给了三个 vblank 不同的等价 timing。
- 尺寸填错的两种典型后果：UI 缩在角落（内核只给了通用模式表）、或被裁（版式与物理屏不一致）。
- **面板物理尺寸 ≠ 应用 UI 版式**：不少机型的 `cfg.json` 是"竖扫方向 + 显示引擎旋转"，
  而 UI 版式是横的。包通过 `cfg_overlay` 把 `width/height/direction` 归一化成与 `[display]`
  一致（详见 `docs/固件包开发教程.md` §6.1）。
- **EDID 怎么被用上**：内核 cmdline 的 `module.param=` 只对 userspace `modprobe` 生效，
  而我们是用 busybox `insmod` 手工加载 `drm` / `drm_kms_helper` 的，
  所以必须显式传 `drm_kms_helper.edid_firmware=Virtual-1:edid/pen.bin`。
- **为什么不用 `virtio-gpu`**：`falcon` 不做 `RESOURCE_FLUSH`，而 virtio-gpu 只在 flush 时
  才把像素传出去（这套构建里 `ModePageFlip` / `ModeDirtyFB` 符号为 0，`DIRTYFB` 返回
  `EPERM`、`SET_MASTER` 返回 `EBUSY`）—— 表现为**首帧之后就冻住**。所以现役虚拟显示设备是
  `bochs-display`（由 runtime 的 `display_args()` 按包的面板尺寸给出）。

### 6.2 显示前端 profile

- `[client].profile` 交给 vmgui（`vmgui/profiles/<名>.toml`），只影响宿主窗口的坐标变换与外观。
- 找不到只告警，不影响开机。`--display vmgui|gtk|none` 决定用哪个前端。

### 6.3 为什么有时要换厂商显示 HAL

部分机型（a6pro/a7pro/x7/x5pro）的显示栈 `falcon/greenui` 直接调 DRM/KMS，宿主的
`bochs-display` 与它在格式协商上不完全一致（`drmModeAddFB2` 的 fourcc、以及它不做
`RESOURCE_FLUSH`）。对这些机型，包内用 `[adapt].replace` 换掉厂商 HAL（或换掉一处小库）
是**已知有效**的做法；但**必须逐机型验证**：同类库的不同版本行为不同，
照抄别的机型打过补丁的 HAL 会崩。

x6pro 是另一种形态：厂商合成器（Weston）依赖 Mali + RGA，QEMU 上两者都不存在，
于是包内**整包换成纯软件合成器**（Debian arm64 的 Weston + Mesa，随包分发解包启动）。
这条路的代价是 25 MB 载荷与"合成器/应用库隔离"的约束，详见 `packs/x6pro/DEVLOG.md`。

### 6.3.1 已知的落点（以 a6pro 那版 HAL 为例）

厂商 UI 框架是 `greenui/falcon`（Skia + 自研 QuickJS 绑定，见 `/usr/lib/libfalcon.so`），
它**硬编码走 DRM/KMS**（`/dev/dri/card0`）而非 fbdev，在虚拟机里会连撞几处格式协商问题。
已定位并打过补丁的清单（**补丁本体在包里**，由 `[adapt].replace` 开机覆盖）：

| # | 问题 | 处理 |
|---|---|---|
| 1 | 平面格式要 ARGB8888/RGB565，宿主只给 XRGB8888 | 三处 fourcc 常量改成 `XR24`（见下方勘误） |
| 2 | crtc/connector 匹配依赖实机 RK 布局 | 分支 NOP |
| 3 | 格式列表循环 off-by-one（`count_formats=1` 时永不比较） | 分支 NOP |
| 4 | 内核 `virtio_gpu_mode_dumb_create` 拒绝 `bpp != 32`（virtio-gpu 时代遗留，现在保留不影响） | `b.NE` NOP + 剥离模块签名 |
| 5 | 面板配置是竖屏 + `bpp:16`，而 UI 本身按横屏画 | `cfg_overlay` 归一化 `width/height/direction/bpp` |
| 6 | 宿主只给通用模式表 → falcon 按 640×480 建 fb，UI 缩在角落 | `[display]` → 生成自定义 EDID |

> **勘误（有人踩过）**：第 1 项的三个 fourcc 是 `movw/movt` 拼出的 32 位常量，两处 `movt`
> 的高半字被写成 `#0x432`（应为 `#0x3432`），得到**非法 fourcc `0x04325258`** ——
> 这正是 `drmModeAddFB2()` 返回 `EINVAL`(‑22) 的原因；另有一处 `movw` 漏改仍是 `ARGB8888`。
> 修好后三处都是合法的 `XR24`（`0x34325258`）。

**成功链路的日志判据**（固件自己会打，可直接查）：

```bat
python scripts\dpctl.py sh -c "grep -a -e 'AddFB2() ret' -e SetPlane /userdata/applog/DictPen_*.log | tail"
```

- `drmModeAddFB2() ret=0` = framebuffer 建起来了（`-22` = EINVAL，见上面勘误）；
- 出现 `drmModeSetPlane failed` 说明平面没更新，屏幕只会停在 fbdev 的启动图。
- 另有 `drmModeSetPlane failed (-13 EACCES)` 这一种：**不致命**，根因是第 3 项那类
  "格式列表比较被改成恒等后，间歇挑到不匹配的平面"，渲染照常，不用去追。

### 6.4 触控桥

- 宿主的 QEMU 窗口点击到达 guest 是**鼠标事件**（virtio tablet → `BTN_LEFT`），
  而笔的 UI 是**触摸 UI**（等 `BTN_TOUCH`）。中间的翻译由包声明的 `touchbridge` 脚本完成：
  它用 uinput 造一个看起来像该机型触摸屏的设备，再把链接到 `cfg.json` 的 `tp` 路径上。
- 桥要处理的三件事（踩过）：`UI_SET_*BIT` 这类 ioctl 的参数是**位号本身**（按值传，
  不能传指针）；坐标是**状态**不是边沿（QEMU 对未变化的绝对轴会去重）；上报的坐标系要与
  `cfg.json` 的 `tp_direction`/`tp_xoffset` 配套。

**鼠标 → 触摸的语义约定**（触摸屏没有 hover，鼠标却有；桥必须把前者做成后者）：

| 鼠标行为 | 桥的翻译 | 理由 |
|---|---|---|
| 未按下时移动 | **不上报** | 触摸屏没有 hover，上报会让 UI 以为一直按着 |
| 按下（`BTN_LEFT=1`） | 用**最近一次已知位置**发 `BTN_TOUCH 1` + 坐标 | 按下那一帧可能没有 ABS（见上面第 2 条） |
| 按下期间的微小移动 | 位移 < `CLICK_SLOP`（典型 4 面板像素）就**吞掉** | 否则按钮自身抖动会被判成拖动，点击永远不成立 |
| 超过 `CLICK_SLOP` 的移动 | 跟随上报 → 拖 / 滑 | |
| 滚轮一格 | 合成一次整屏上下 swipe | 笔的列表靠手指滑动滚动，没有滚轮 |

阈值（`CLICK_SLOP`、swipe 步数与步间隔）都写在桥脚本顶部的常量区，按机型手感调。

宿主侧的 `dpctl pointer` 只在**宿主窗口**上画一个落点提示环（Tk 置顶窗口、点击穿透），
用来调试"我点的位置和 UI 收到的是不是一回事"——它**不转发输入**。

- 相关个案（镜像、方向、点击不跳页）见 `docs/疑难排查.md` §1、§2。

## 7. 宿主基线与"零机型"自检

### 7.1 宿主提供什么

| 能力 | 在哪 | 与包的关系 |
|---|---|---|
| 命令面 `packs/up/down/status/wait/sh/shell/put/get/screenshot/tap/license/sysinfo/view/pointer` | `scripts/dpctl.py` | 与机型无关 |
| 端口 SSH 2222 / 串口 4444 / monitor 4445 / QMP 4446 / adb 15037 / BT 4447 | 同上 | 与机型无关 |
| 通用 arm64 内核 + 通用 initramfs | `tools/kernel-root-gui/`、`images/initramfs.cpio.gz` | runtime 可覆盖 |
| 虚拟 Wi-Fi/蓝牙/电量/激活脚本 | 宿主 initramfs 与 `scripts/*.sh` | 包只声明开关 |
| 显示前端 vmgui | `vmgui/` | profile 由包给 |
| 状态盘、传输、调试、值守脚本 | `dpctl.py` | 按包名分盘 |

### 7.2 可执行的自检判据（"宿主零机型"不是口号）

```bat
:: 1) 无包不崩：临时移走 packs\ 与 downloads\，这两条应友好退出而不是抛异常
python scripts\dpctl.py packs
python scripts\dpctl.py up --pack nothing

:: 2) 宿主代码里不该出现机型名（runtimes/ 的平台参数说明除外）
::    期望 0 命中
git grep -ni "a6pro\|libfalcon\|pear\|560x170" scripts\ dpctl.py vmgui\

:: 3) 一个宿主多台机器互不污染：分别 up 两个包，各自能起
python scripts\dpctl.py up --pack a6pro
python scripts\dpctl.py up --pack x6pro

:: 4) runtime 插件"不改宿主即注册"：丢一个 runtimes\_probe.py 应被跳过；
::    丢一个 runtimes\probe.py（新 name）应出现在下面这条的输出里
python scripts\dpctl.py packs
```

### 7.3 可传播文件由包声明（不在宿主里写死）

打"可传播代码包"（`python scripts\package.py`）时，固件包只带**描述性文件**，
默认是 `pack.toml` / `README.md` / `cfg.json.overrides` / `touchbridge.pl`。
包想额外带自己的说明文件（例如 `DEVLOG.md`），在 `pack.toml` 里声明即可：

```toml
[dist]
include = ["DEVLOG.md"]        # 包内相对路径；宿主按声明放行
```

纪律：`*.img` / `*.so` / `*.pem` / `id_*` 的**硬拦截优先于声明** —— 声明了也不放行，
而且会在自检里直接报错。

## 8. 接口变更纪律

1. 改任何插件点的接口（`Runtime` 的方法、`[adapt]` 的键、`pack.env` 的键、`/patches/` 下的
   约定路径），**必须同步改本文件的表格**。
2. 不要在两处写契约：其它文档只写"看本文件 §N"。
3. 改完跑一遍 §7.2 的四条判据 + 至少一台机器的 `up → wait → screenshot → down` 回归。
4. 跨文档引用**必须点名文件**：写 `docs/xxx.md`（要精确到节就写 `docs/xxx.md` §N 或
   `docs/xxx.md#锚点`）。**只写《标题》**的引用一律要改掉 —— 标题会改，读者按它找不到地方。
